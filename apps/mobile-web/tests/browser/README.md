# Mobile recovery browser validation

Run `node apps/mobile-web/tests/browser/recovery.mjs` from the repository root. It uses the installed web Playwright dependency and mobile Vite configuration, starts an isolated dev server on port 15743, and writes results to `/tmp/bigbud-mobile-route-recovery-results.json`.

Run `node apps/mobile-web/tests/browser/delivery.mjs` for the existing-thread delivery path. It verifies the displayed model and thread modes on the existing-thread `thread.message.submit` command, suppresses rapid duplicate activation, and preserves newer typing when the held acknowledgement arrives.

Run `node apps/mobile-web/tests/browser/visual-parity.mjs` to capture deterministic mobile screenshots at `/tmp/bigbud-mobile-visual-parity-idle.png` and `/tmp/bigbud-mobile-visual-parity-composer.png`, plus a JSON result at `/tmp/bigbud-mobile-visual-parity-results.json`. The fixture renders an empty conversation with the centered bigbud logo and a composer containing `What are we working on?`. The desktop floating assistant is not mounted by this mobile fixture, so the result records that reference-state limitation.

Run `node apps/mobile-web/tests/browser/drawer-lifecycle.mjs` to exercise rapid close/reopen during the Drawer exit transition, reduced-motion closure, and forgetting the connection while the Drawer is closing. It verifies route state, focus restoration, scroll-lock cleanup, retained-content cleanup, and page errors.

Run `node apps/mobile-web/tests/browser/geometry-lifecycle.mjs` to verify that a reader's scroll position survives late transcript growth, Latest restores following, the idle logo is centered against the transcript viewport, and approval controls have 44px targets reachable at a 390×320 viewport. The same actual-App run checks pending-question title/detail focus, 44px choices, Space selection, Next/Previous progress and local free-text preservation at that viewport; it does not submit a remote answer.

Run `bun run --cwd apps/mobile-web test:browser:visual-viewport` for keyboard geometry that changes the visual viewport without resizing the layout viewport. The actual-app fixture keeps the composer and navigation inside the visible area, preserves the draft, focus and selection, checks that pinch-scale measurements do not reflow the shell, and restores full height when the keyboard is dismissed. It uses port 15749 and a synthetic `VisualViewport` event source; it does not certify physical iOS/Android keyboards or native pinch gestures.

The test renders the actual `App` thread route with its session provider, RPC client and codecs, recovery controller, React Query cache, thread view and composer. Playwright intercepts WebSocket messages with deterministic protocol responses; it does not substitute component freshness props. It closes the socket, requires a new baseline/subscription, withholds the completion marker to check Send gating, then returns the exact old-server unknown-request defect to exercise legacy fallback. The direct-link baseline must request selected history, and the summary fixture has no messages. It checks cached conversation text, draft, focus, selection, enabled typing, legacy timestamp and absence of automatically dispatched commands. A second rapid replacement can exhaust the shared automatic retry budget; the harness then exercises explicit Retry without moving focus. A final running-thread phase delivers `resync-required`, verifies that Stop remains enabled while stale, clicks it, and inspects the real serialized command for one `thread.turn.interrupt` targeting that thread with a command ID. The harness withholds the command result and verifies that the running UI remains, without claiming Stop succeeded. Send is gated in the earlier stale and refreshing phases; approval/question route geometry and local question progression are covered separately by `geometry-lifecycle.mjs`; remote approval/answer delivery is not inferred from those local checks.

Validated on 10 September 2026 with Chromium 147.0.7727.15 at a 390×844 touch/mobile viewport. No browser page errors occurred. The authenticated deployed server and physical iOS Safari/Android Chrome resume behavior are not covered: physical devices were unavailable. The actual Effect legacy-server protocol evidence separately exists at `/tmp/bigbud-mobile-rpc-review/probe.ts` and `results.json`.

Run `node apps/mobile-web/tests/browser/baseline-matrix.mjs` to capture the mobile access plan's phase-5 baseline matrix into `/tmp/bigbud-mobile-baseline/`: chats, thread, still-connecting (a refused first connection) and pairing-unreachable, at 360/390/430 portrait, 390 landscape and a 390×460 keyboard-open approximation, in light and dark themes. `results.json` records horizontal overflow and page errors per capture, and the script exits non-zero if any occur. The shared `/mobile-ws` stub lives in `mobileWsStub.fixture.mjs`. The keyboard state is approximated by viewport height; real on-screen keyboards and physical devices are not covered.

Fixture sessions expire in 2099. Before 13 November 2026, `scheduleMobileConnectionExpiry` passed that delay straight to `setTimeout`, which fires immediately for delays above 2³¹−1 ms. The fixture session therefore expired at once, the client only sent `Interrupt` frames, and these harnesses stalled on the loading screen. The scheduler now re-arms in bounded steps, so the harnesses work again.

The still-connecting matrix fixture pauses the browser clock before navigation, then advances it in 500 ms steps until the expected notice is visible. The socket still targets a refused loopback connection and uses the real retry controller. This prevents host startup load from exhausting the transient retry state before capture; it is not a measurement of real-time reconnect latency.

Run `bun run --cwd apps/mobile-web test:browser:isolation` for a same-document thread route transition with a persisted uncertain approval. It asserts that thread B never checks thread A's command ID or persists its decision, and that B can compose a new message. The fixture uses port 15747 and no real account.

Run `bun run --cwd apps/mobile-web test:browser:rejection-resume` for the actual app providers/hooks with a synthetic permanent baseline rejection. On a selected thread, it exhausts the real RPC retry policy, triggers focus-driven client replacement, verifies no automatic baseline rebuild, then verifies explicit Retry rebuilds once. Leaving and returning to the thread also verifies that a genuine route-scope change permits a new read. The page clock is controlled; this is not a real-time latency measurement. It uses port 15748 and no real account.

The P5 matrix now includes long pending approvals alongside chats, thread, reconnecting and unreachable pairing states. Each is exercised at 360/390/430 widths in portrait, landscape and reduced-height keyboard simulation, in both themes (90 captures). Thread/approval captures also check that Send or Approve remains inside the viewport. Reduced height and textarea focus do not prove physical keyboard behavior.

Additional P5 states cover initial loading (held fixture baseline and paused clock), empty thread, user questions, expandable work log and the model menu. The full matrix has ten states × nine viewport layouts × two themes (180 captures). Keyboard assertions cover selecting an answer with Space, toggling the work log with Enter, and opening/dismissing the model menu with focus returned to its trigger. These are narrow interaction checks, not a full accessibility audit or physical keyboard acceptance.

For a focused fixture rerun, set `MOBILE_MATRIX_STATES` to comma-separated state names, for example `MOBILE_MATRIX_STATES=question,work-log,model-picker node apps/mobile-web/tests/browser/baseline-matrix.mjs`. The latest `results.json` contains only that run's captures; do not count older PNG files in the output directory as current evidence.

`parity-reference.*` and `src/test-fixtures/MobileParityReference.*` provide a separate current-component comparison with disposable data. It mounts actual current desktop components beside their mobile counterparts for loading, editor, approval, question, markdown, work-log wrapper, opened model menu, header, connection error, thread rows and empty state, plus a controlled ready-shell reference. The current fixture has twelve surfaces (144 images across two clients, three widths and two themes); runtime qualification of the added full-shell reference remains a separate gate. Results include computed geometry, themes, menu rows/search input and application-network rejection evidence; screenshots are saved before touch-target assertions report a regression.

The Linux driver requires a separately reviewed, network-isolated fixture workspace with existing Electron, Playwright, Vite and system libraries. It uses a disposable profile, disables Vite HMR and rejects backend/external requests. It does not launch the actual desktop application or use a real account. Do not run it against a profile, the validation proof workspace or an unreviewed source archive. The orchestration evidence records exact source/dependency manifests and the read-only boundary before and after execution.
