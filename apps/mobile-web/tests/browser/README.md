# Mobile recovery browser validation

Run `node apps/mobile-web/tests/browser/recovery.mjs` from the repository root. It uses the installed web Playwright dependency and mobile Vite configuration, starts an isolated dev server on port 15743, and writes results to `/tmp/bigbud-mobile-route-recovery-results.json`.

Run `node apps/mobile-web/tests/browser/delivery.mjs` for the existing-thread delivery path. It verifies the displayed model and thread modes on `thread.turn.start`, suppresses rapid duplicate activation, and preserves newer typing when the held acknowledgement arrives.

The test renders the actual `App` thread route with its session provider, RPC client and codecs, recovery controller, React Query cache, thread view and composer. Playwright intercepts WebSocket messages with deterministic protocol responses; it does not substitute component freshness props. It closes the socket, requires a new baseline/subscription, withholds the completion marker to check Send gating, then returns the exact old-server unknown-request defect to exercise legacy fallback. The direct-link baseline must request selected history, and the summary fixture has no messages. It checks cached conversation text, draft, focus, selection, enabled typing, legacy timestamp and absence of automatically dispatched commands. A second rapid replacement can exhaust the shared automatic retry budget; the harness then exercises explicit Retry without moving focus. A final running-thread phase delivers `resync-required`, verifies that Stop remains enabled while stale, clicks it, and inspects the real serialized command for one `thread.turn.interrupt` targeting that thread with a command ID. The harness withholds the command result and verifies that the running UI remains, without claiming Stop succeeded. Send is gated in the earlier stale and refreshing phases; approval/question button checks remain the separate synthetic component evidence rather than an integrated-route claim.

Validated on 10 September 2026 with Chromium 147.0.7727.15 at a 390×844 touch/mobile viewport. No browser page errors occurred. The authenticated deployed server and physical iOS Safari/Android Chrome resume behavior are not covered: physical devices were unavailable. The actual Effect legacy-server protocol evidence separately exists at `/tmp/bigbud-mobile-rpc-review/probe.ts` and `results.json`.
