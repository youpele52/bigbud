# Offline A-to-B handoff boundary checker

This checker compares two local JSON inputs: an independently frozen plan and normalized observations. It checks that A's managed processes and DB handles retire before B starts, B takes over and hydrates the same DB before opening Rust SSH admission, and attempts through the frozen legacy entry points receive fence refusals after admission. It does not inspect artifacts, processes or SQLite, take a lock, start an app, or contact the network. Supply only redacted identifiers and digests; never supply credentials, raw epoch secrets, process arguments, or user-profile data.

A conforming result does not authenticate the observations, establish that the rehearsal was isolated, prove that the capture or inventory was complete, or qualify the release. This checker covers the verified-exit path only. It does not infer retirement from a process snapshot, socket absence, or an idle interval. Acknowledged retirement of a retained non-SSH terminal host, stale-write refusals, pane compatibility, and build A's release precedence remain separate evidence obligations. Do not use this result as a substitute for the underlying observations or for the [matrix](../matrix/README.md).

## Input contract

All objects have exact fields. Use the [matrix token syntax](../matrix/README.md) for identifiers, lowercase SHA-256 digests, and distinct positive event sequences in a single recorder ordering (not wall-clock timestamps).

**Plan**: `{ kind: "forward-boundary-plan-v2", binding, profileInstance, dbInstance, metadata, aInventory, legacyEntries, bWriterImageSha256 }`. Passive v1 records do not pass v2.

- Copy `binding` from the independently reviewed **required** matrix cell. Freeze `profileInstance` for the disposable rehearsal profile and a stable redacted `dbInstance` for its actual underlying DB file identity, not a pathname or content hash. Do not reuse an identity token for another profile or copied DB.
- `metadata` is `{ schemaCeiling, schemaSha256, migration, migrationSha256 }`, using the same normalized definitions as the [rollback checker](../rollback/README.md). `bWriterImageSha256` identifies the B backend process that opens the DB, not the distribution artifact or the separate Rust owner.
- After recording the initial process identities and before drain, freeze `aInventory` independently of the reported exits. Each entry is `{ component, role, process: { instance, imageSha256 }, dbHolder }`, with unique component and lifetime tokens, role `launcher` or `transport`, and `dbHolder` a boolean for whether that instance holds the DB before drain. Include at least one launcher and DB holder; a launcher may also hold the DB. Cover every relevant managed A process, including detached launchers, masters, relays, and SSH PTYs as applicable. A lifetime token must distinguish identities across PID reuse. Reviewers must check the inventory against actual sources of authority; the tool cannot discover omissions.

- `legacyEntries` lists `{ id, component, callerImageSha256 }` for every supported old entry point in the upgrade path, not just the processes live at `before`. Freeze the route IDs, their launcher components and the expected calling image digests before the attempts. IDs are unique; list each distinct route even if it shares a launcher or caller. Every `aInventory` launcher must have an entry, transports must not, and a dormant launcher can have entries without an `aInventory` row. Review the list against the shipped launch surfaces; the verifier cannot discover a missing route or dormant component.

**Observations**: `{ kind: "forward-boundary-observations-v2", binding, profileInstance, a, b, capture, before, retirements, boundary, bStart, takeover, admission, relaunches }`.

- `binding` and `profileInstance` identify the observed rehearsal. Each of `a` and `b` is `{ artifact: { id, build, sha256 }, executor, metadata }`; their executors are `legacy-ts` and `rust-owner`, respectively. Measure artifact and metadata identities independently of the plan.
- `capture` is `{ scope: "process-lifecycle-db-authority-and-legacy-relaunch", complete: true, lostEvents: 0, fenceContinuous: true, otherAStarts: 0, otherBStarts: 0, legacyTransportStarts: 0, endSeq }`. Keep the capture and fence continuous from `before` through every refusal and the reviewed delayed fallback/retry window. Record `endSeq` as a final marker after that window. Counts exclude already-running A lifetimes at `before` and the expected B writer and owner. Include legacy-managed SSH launches through wrappers or detached processes, not only launches with an A artifact identity. Probe clients that do not regain managed launch authority are not A starts. Unknown values are not zeros; these counts alone cannot establish a refused attempt.
- Snapshots are `{ seq, fence, db: { domain, instance, metadata, logicalSha256, holders } }`. `fence` identifies the same continuously held exclusive release fence. `holders` lists process lifetime tokens holding handles to the canonical DB, regardless of path aliases. `logicalSha256` fingerprints the WAL-visible committed disconnect membership, timestamps and target sequences under one canonical normalization, excluding the rotating writer epoch. Do not hash raw DB or WAL bytes.
- `before` is the initial snapshot with exactly the frozen A DB holders. `retirements` lists one `{ component, exit: { instance, imageSha256 }, status: "verified-exit", seq }` for every frozen A lifetime. Each verified exit must be after `before` and before `boundary.snapshot`.
- `boundary` is `{ snapshot, writerEpoch }` after A exits and its handles close. It records zero holders and the final committed state left by A; the state can differ from `before` if A completed work while draining. The epoch is a redacted equality token or `null` if absent. `bStart` is `{ seq, process: { instance, imageSha256 } }` for the B backend, after that boundary.
- `takeover` is `{ snapshot, previousEpoch, writerEpoch, hydratedLogicalSha256, outcome: "committed-cas-and-hydration" }`, recorded after B's takeover transaction commits. Its snapshot has exactly the B backend as holder and the same committed disconnect state as `boundary`. `previousEpoch` is the actually compared value (`null` for install-if-absent), not an echoed guess. `writerEpoch` must differ from the boundary epoch. Fingerprint the actual hydrated values with the same normalization as `logicalSha256` for `hydratedLogicalSha256`.
- `admission` is `{ seq, fence, dbInstance, writerEpoch, owner: { instance, imageSha256 } }`. Observe actual opening of Rust SSH admission after takeover, on the same fence, DB and new epoch. The owner must match the cell's verified owner image and have a different process lifetime from the B writer and every A process.

- `relaunches` contains exactly one `{ request, result }` pair per frozen entry. Record the actual invocation as `request: { attempt, entry, seq, caller: { instance, imageSha256 }, dbInstance }` and its correlated response as `result: { attempt, seq, outcome: "refused-by-legacy-fence", fence, dbInstance }`. Capture both events; do not derive either from plan values, link to a checklist, or normalize a timeout, unsupported role, generic exit, missing binary or absent process as a fence refusal. The confirmed response must come from the managed admission fence or the explicit retirement guard on the entry, not the probe harness. `attempt` is a unique recorder correlation token, `entry` is the observed route, and `caller` is its actual initiating process, not a retired A lifetime. Both events target the same canonical DB; the refusal must bind to the same fence used for B admission. All requests are after admission, responses follow their matched requests, and all sequences are distinct and before `endSeq`.

## Run locally

From the repository root with existing Bun dependencies:

```sh
bun run protocol/ssh-owner/release-evidence/forward/verify.ts /path/to/forward-plan.json /path/to/forward-observations.json
bun run vitest run --config protocol/ssh-owner/release-evidence/forward/vitest.config.ts protocol/ssh-owner/release-evidence/forward/check.test.ts
```

Exit 1 refuses malformed, incomplete, uncertain or mismatched observations without a report. Exit 0 reports `forward-boundary-observations-conform` and identifies the cell and the counts of matched retirements and observed relaunch refusals. There is no qualification or acceptance field. The tests use synthetic records only.
