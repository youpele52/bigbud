**Date:** 12 October 2026

**Baseline:** Clean main worktree, `plan/terminal-rust-gpu-reliability`, `91154fa9c086e1d47a3bbddfea4a8d56a35be44d`. No staging, commit, push, native lifecycle/configuration changes or automatic trust acknowledgement.

## Diagnosis

The reported **Native service trust consent required** state is intentional server enforcement, not a missing V2 SDK or sign-in flow. `Application.discovery.ts:8-46` checks health/capabilities before acknowledgement, publishes a warning with no models and never acquires the manager/SSE. `Application.consent.ts` separately fences execution and revoked revisions. Enabling OpenCode alone does not acknowledge host-user execution.

The actual UX defect was the unavailable provider row in `ProviderModelPicker.tsx`: it was disabled, with a truncated status and no way to reach setup. The existing `ProviderCard.nativeTrust.tsx` explicit switch works, but is inside collapsed details. A second gap was that `ProviderModelPicker.modelList.tsx` accepted `unavailableMessage` without rendering it, so an empty locked picker could say only **No models available**.

Parent read-only diagnostics reported installed `opencode v2.0.26` and a registered literal-loopback service. That matches the installed client pin; it does not establish authenticated model inventory or successful execution. Neither session inspected native tokens/configuration nor submitted a live prompt. No restart/start was needed for diagnosis.

## Official V2 evidence and preserved boundaries

- [Client](https://opencode.ai/v2/docs/build/client): `@opencode/client` is the V2 HTTP client. Service `discover` checks without starting; `ensure` can start; `headers` creates authentication headers. The installed `2.0.26` Promise entrypoint remains intentional with bigbud's existing Effect beta. Context7 `/websites/opencode_ai_v2` was consulted.
- Parent audited installed `dist/promise/service.js:39-120`: `ensure` can also clear registration, terminate/replace a daemon and invoke stop/signals. It is not a harmless setup action. No `ensure`, stop, service restart, native administration, isolated fallback or dependency/Effect upgrade was added.
- [Permissions](https://opencode.ai/v2/docs/permissions): native shell authority is host-user authority, not a bigbud sandbox. This acknowledgement is bigbud's boundary, not a native OpenCode prerequisite; it must not be inferred or automatically granted.
- The [API-first ledger](opencode-v2-api-client-2026-10-11.md#local-root-check-acceptance--12-october-2026) closes earlier root failures. Historical failures must not be reported as current. Outstanding native Windows/WSL/other platform qualification and unsupported rewind/fork/steer/continuation are separate from this picker defect; this change does not claim to implement or qualify them.

## Small fix

- Unavailable **local** OpenCode now offers **Set up OpenCode**, navigating to the existing providers route with `providers=["opencodeV2"]`, which expands its details. Setup navigation does not select a model/provider or write settings.
- Empty locked OpenCode pickers render the supplied status; only local targets receive the setup action. Ready/full-catalog behavior remains unchanged.
- The shared picker also runs in mobile, which has no providers settings route. It displays desktop/web setup guidance instead of navigating to a missing route. Unsupported remote workspace rows retain their disabled state.
- Existing settings consent, reset/revocation, native mode/service-file fences and background refresh are reused, not replaced. A broad setup redesign or implementation plan was unnecessary for this issue.

## Manual unblocking

1. Choose **Set up OpenCode**, or open **Settings → Providers → OpenCode** and expand details.
2. Enable OpenCode and use **Shared TUI service**. Read the host-user/plugin/history explanation.
3. If you accept it, explicitly switch on **Trust native service execution**. No other action grants trust.
4. Wait for discovery or click **Refresh provider status**. Select an available native provider/model in a new OpenCode chat. Public setup-only models are not authenticated account proof.
5. If a new error appears, follow that specific status. Configure/connect the provider in the native TUI if required; missing service means the user must open/start it themselves. Changing mode/service paths may require bigbud restart as documented. Do not use `Service.ensure`, automatic trust, history deletion or a daemon replacement to bypass this gate.

See [provider usage and limitations](../reports/providers-opencode-v2.md) for the existing recovery/security contract.
