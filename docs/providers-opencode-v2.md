# OpenCode

OpenCode uses the V2 integration for all new chats. Legacy `opencode` chats remain read-only history; create a new OpenCode chat instead of continuing, resuming or retrying them. Internal V1/V2 routing and storage remain distinct and are never silently migrated. V2 is enabled for fresh installations, but is not the global default over other providers. Existing settings without an explicit V2 enable stay disabled: old sparse settings cannot distinguish a prior disable from never configured. Explicit disables and unrelated choices are preserved; enable OpenCode in Providers settings when ready. **Shared TUI service is the default connection mode** for new configuration: it uses your installed native service, accounts, configuration, agents, skills and MCP without credential copies or another sign-in. The client dependency remains **2.0.26**. Runtime **2.0.26+ is recommended**, not required: **2.0.24 and 2.0.26** have disposable native/shared-application qualification. Unknown versions remain rejected until qualified. A qualified older runtime receives one nonblocking update toast per app session and remains ready.

**Current preview scope (9 October): shared native local-service chat/coding plus path-first attachments across providers.** Shared/default and advisory-version policy supersede the historical exact-runtime/private-default policy. Existing approval/admission/no-replay requirements remain. Attachment failures are action-specific, not permanent composer warnings.

## Use your existing TUI account

1. In **Settings → Providers → OpenCode**, enable the integration with **Shared TUI service** selected. No binary/profile path or second sign-in is required. Historical private paths imply isolated mode until you explicitly select shared; paths/history are not removed.
2. Shared storage qualification is **macOS only**, using read-only registered-process open SQLite handle metadata, never database contents or a guessed HOME. Missing/ambiguous storage fails closed. Linux/Windows and remote shared targets remain unsupported; explicit isolated mode retains its existing qualified routing.
3. If no healthy service is registered, open your installed V2 TUI or start its native service yourself. bigbud never starts a competing daemon, upgrades the CLI or replaces your service. Automatic safe missing-service startup is not claimed.
4. Select the exact native provider/model. Connected native inventory ranks ahead of public-only setup options. **Provider not connected** is setup guidance, not a silent model switch. OpenAI and Azure remain distinct even for the same model slug. Native account metadata refreshes every 15 seconds while enabled; no credential endpoint or vendor prompt is used.
5. Restart bigbud after changing connection mode or service/profile paths. Old chats remain bound to their original storage: reopen their original mode or create a new chat. No automatic migration, rebind or resend occurs. Path-first desktop/browser upload, paste/drop, workspace and canonical thread references remain available. Mobile remains text-only.

Shared mode borrows one authenticated loopback client/event hub across local Locations. Disable/shutdown detaches its subscriptions and interrupts only exact bigbud-owned sessions; the daemon and unrelated TUI history remain alive. Transport loss/registration replacement is not physical-exit proof and never clears mutation quarantine. A native-generation change currently requires app restart; uncertain admissions remain blocked.

**Advanced isolated mode:** select a separately installed 2.0.26 executable and new private profile outside workspaces. bigbud initializes its own profile/coding plugin only in this mode. Never select/copy your normal native profile. V1 credentials/configuration are not overwritten.

## Full model catalog

V2 uses the same grouped/searchable/recent model picker as V1 and Pi. Friendly provider/model names come from real metadata; persisted routing keeps the exact subprovider and model IDs, so identical model slugs on different providers remain distinct. Native discovery supplies custom endpoints, aliases and exact variants. Public-only entries have unknown native capabilities/variants, not guessed effort settings.

The pinned V2 `model.list` and `provider.list` APIs return **available** entries, not the full catalog. bigbud separately reads OpenCode's official public [model feed](https://models.opencode.ai/api.json), merges native entries over it, and marks missing native entries as setup-only. Retired V1 provider aliases, deprecated models and non-text models are excluded. Available/free models do not prove an authenticated account. A provider's automatic activation is not used as authentication evidence.

Public catalog reads send no credentials, reject redirects, are bounded to 5 seconds / 8 MiB / 1,000 providers / 10,000 model entries, and use a scoped single-flight one-hour cache with a 30-second failed-refresh retry window. A temporary failure retains the last good catalog with a warning. The native fetch-disable flag remains intact: it disables native network refresh, **not** its bundled snapshot. There is no V1 cache/profile/credential reuse and no change to stream/event/other response bounds.

Before new history/model changes/prompt admission, bigbud rechecks the exact native model/variant. Unavailable selection fails before mutation without fallback. Accepted-request replay does not require current availability. Connect your provider in the native TUI; shared metadata refresh detects changes. Catalog/account metadata is not proof of successful billed execution.

## Access and limitations

- **Supervised:** co-located native file/shell operations ask for approval.
- **Auto edits:** shared mode allows ordinary native edits and asks for other native actions; this is host-user trust, not a bounded-edit sandbox. Isolated mode retains bounded broker edits and native ask fallback without its helper.
- **Full access:** trusts ordinary native tools with host-user filesystem, process, and network authority. This is **not a sandbox**; external-directory requests still ask.
- Shared mode rejects remote/synthetic Locations without local fallback. Isolated mode retains target-bound broker handling.
- `bigbud_shell` is a distinct optional macOS-contained, no-fork/no-network broker tool. Its limits do not apply to approved native shell commands.
- Typed supported forms preserve native field/option identities. Conditional, hidden, external and other unsupported presentations cancel with a limitation warning instead of submitting invented answers or leaving a permanently waiting request.
- Saved native project approvals can override session `ask` rules. bigbud fails closed when such grants exist; review them in OpenCode. It never deletes user approvals or sends `always`. Shared mode never rewrites user MCP/plugins; canonical child-thread tools are not injected globally and native subagent spawning is denied for app-owned sessions.
- Attachments use verified immutable managed snapshots, never arbitrary desktop `sourcePath` rereads. Target-reachable paths are preferred with existing reading tools and approvals; shared bounded document/OCR text is supplemental. Native image/PDF delivery is retained where the adapter supports it. V2 native media supports PNG/JPEG/GIF/WebP, not PDF/Office binaries: those use extracted text or reachable reading tools. Known visionless V2 models receive OCR only, with explicit visual-loss limitations; unavailable required extraction fails before model mutation/prompt admission.
- Text/CSV/code and DOCX/PPTX/XLSX extraction reuse existing readers. PDF text and OCR depend on already available system helpers; nothing is installed automatically. Scanned-PDF OCR is only a preview of up to the first three pages. Extracted item text is limited to 32,000 characters and supplemental aggregate text to 60,000, plus truncation markers/metadata; notices identify truncation/unavailable extraction. OCR is not equivalent to visual analysis, and extracted PDF/Office text does not preserve every chart/layout detail.
- Workspace references never read same-named host files for remote workspaces. V2 remote references use the target-bound broker; managed uploads use supported content fallback when the runtime cannot reach host snapshots. Other providers retain workspace references for their existing target reading tools, without promising automatic remote document/OCR extraction. Directory references remain tool references and thread references expand canonically. Unsupported/denied remote reads fail without local fallback.
- V2 persists immutable attachment preparation in **private bigbud state**, not the shared native profile, before admission. Replay does not rerun OCR/reread snapshots/resend. Historical text-only fingerprints and bounds remain. The 10 MiB stress probe remains excluded. See [attachment evidence](./validation/shared-attachments-2026-10-09.md).
- Native rewind, fork, steer, transparent process-loss recovery, and continuation are unsupported. Inspection is best effort. Idle model/variant switching preserves native history, verifies the selection by readback and blocks further prompts on uncertain mutation outcomes. bigbud-owned access/workspace/browser instruction entries refresh before new prompts without replacing native/user entries. Native owned deletion and remote protocol completion remain tracked in the [completion plan](./plans/2026-10-08-opencode-v2-preview-completion-plan.md).

## Disable and rollback

Disable OpenCode in Providers settings; V1/Kilo IDs, configuration, and history remain independent. Legacy OpenCode is retired, not a rollback runtime. Stop/archive/shutdown retain V2 native history and durable replay protection. Never replay uncertain work through another provider: a lost acknowledgement does not prove nothing ran.

Before upgrading a used **V2-owned** profile, back it up while its owned process is stopped. Reverting a package or executable pin does not undo native database migrations. Restore the matching profile backup when downgrade compatibility is unproven. The 2.0.19→2.0.26 disposable probe is evidence only for its tested fixture, not a guarantee for every user's database.
