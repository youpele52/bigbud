## Initial feasibility blockers (historical; follow-up evidence below)

1. Public APIs expose no import/export contract for parser/decoder carry, saved cursor, tabs, margins or built-in partially accumulated OSC/DCS. Cells and serialize cannot reconstruct these fields; the executable counterexamples disprove that shortcut.
2. `CoreService.triggerDataEvent(data, wasUserInput)` distinguishes origin **internally**, but public `onData` conflates user input and emulator replies. The prototype replays query side effects; it is intentionally not promoted to a checkpoint. The eventual extension also needs bounded awaitable response admission, not a synchronous unbounded outbox.
3. No reviewed fork patch, complete versioned schema, reproducible **paired** browser/headless artifacts, async-handler export contract, validated import allocator, or import/capture peak-memory accounting exists in this slice. Field-name verification is an inventory check, not completeness proof.
4. The bounded operation-replay prototype matches nine tiny synthetic continuations while retaining source from generation zero, including split UTF-8 and subsequent resize. It rejects exhaustion rather than truncating. This neither compacts state nor proves arbitrary resize/control history, full attributes or response ledger equality. It has no product integration or disk persistence.
5. Maximum configured geometry/scrollback and paired headless→browser full-state differential fuzzing remain unmeasured. A maintained extension should be developed/reviewed as a separate milestone before native-owner design implementation or any automatic cold recovery.

No dependency publication, upstream PR, fork acceptance, native parity or exactness guarantee is claimed. D3–D6 remain binding; no gate is relaxed.

## P6a binary follow-up — selected-state code and measured remaining blockers

The isolated owned extension now has a fixed **schema 2**, ≤48 KiB binary pages, lossless cell planes and UTF-16 strings, SHA-256 digest, build/schema/option/Unicode/handler fingerprints, bounded metadata scan, borrowed payload slices, pre-materialization cross-reference validation and fixed-field commit. Owned envelope/options/page-list containers are frozen so a caller cannot resize/re-digest custody while retaining a smaller reservation; page-content drift fails digest validation. No arbitrary payload-selected constructor or `Object.assign` service replacement is used. This supersedes the four-million-JSON-value amplification failure; it does **not** approve a production maintained fork or complete exact-state schema. Generator/verifier and extension source hashes, both vendor input hashes and both generated output hashes are checked before execution. Current documented commands are in the harness README.

Supported fields in the inventory now capture/import both logical buffers and typed cells, wrap/saved cursor/attrs, charset/tabs/margins/modes (including cursor shape/blink), title/icon stacks, decoder carry, partial CSI/OSC/DCS and built-in handler bindings/params, mouse dedup/wheel state, and next link ID. **80 headless and 80 browser continuations** pass against an independent selected-state oracle, including 64 deterministic cut/resize cases. Import emits no observed data/bell/title/resize events; continuation response bytes match in both targets. Four codec/artifact tests cover independent SHA-256, split pages/surrogates, bounded reservations and source/build/input/output provenance tampering. Recomputed-digest corruption of counts/types/enum/cell/parameter/active-handler references also refuses without target mutation.

Full existing hyperlink/marker ownership remains explicitly refused: the paired upstream service stores marker disposal closures and buffer references, not only numeric IDs. Partial OSC 8 before link creation is supported and its continuation checks link/marker state independently. Palette/color-query state remains refused (including a partially collected known color query); upstream headless lacks the browser's palette owner/query path. Unsupported custom handler/Unicode sets, window/Windows options and unsettled async/callback cuts also refuse. Future maintained source-level service changes, origin-aware awaitable response admission and trusted ordered pixel metadata are still necessary; this experiment implements none of the production authority/response ledger/native routing.

## Focused SECURITY correction after independent CODE acceptance

Parent CODE accepted the **supported experimental projection**, finding no confirmed fidelity, accounting or failure-atomicity bug in that bounded slice; it did not accept universal exact readiness or field completeness. Parent SECURITY requested two corrections, so its earlier review was **not acceptance**. This follow-up fixes those issues and the CODE theme-refusal qualification, without changing auth models/specs, accepted Rust, production xterm, dependencies, routing, geometry or budgets.

1. **Execution provenance:** the previous verifier incorrectly allowed unrelated output bytes when their hashes were supplied by a coordinated mutable manifest. Expected execution hashes now come from a read-only deterministic rebuild of trusted reviewed repository source and pinned vendor inputs using Bun 1.3.14, independently of the candidate output/manifest. Both actual outputs AND manifest hash metadata must equal that derivation. The positive fixture uses the real generator. Coordinated one/both-output + manifest replacement, raw vendor bytes with their valid known hashes, and metadata substitutions all refuse before execution. Verified immutable source strings are retained privately and used by every runner, eliminating a later file reread as execution authority. The checkout/runtime/toolchain are the explicit trust anchors; this is not remote signing or a hostile-JS sandbox.
2. **Page backing custody:** captured intrinsic TypedArray buffer/type/offset/byteLength/length and ArrayBuffer byteLength/resizable/detached accessors inspect real backing stores. Genuine SAB views fail the ordinary-ArrayBuffer brand even when `.buffer` is shadowed by an ordinary AB or a getter. Own metadata/iterator shadows, view Proxies/custom prototypes, resizable and detached/stale WASM-backed views refuse without invoking caller getters/traps. Hashing uses indexed bytes, never caller iterators. Only bounded trusted page-list metadata is copied; bytes stay borrowed from fixed nonshared ABs across a synchronous no-await/no-caller-callback validation→commit lane. Frozen containers alone were not the fix, and no shared cross-worker custody is claimed.
3. **Theme qualification:** only an initially empty theme with no public replacement is supported. Nonempty constructor themes, public setters/options replacement, revert-to-empty and observable in-place theme mutation refuse capture/import. This is an explicit experimental restriction, not palette restoration. Existing OSC palette/known partial color-query and hyperlink refusals remain; the independent oracle is selected-state evidence, not an omission-proof full inventory.
