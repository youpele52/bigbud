## Owner production and activation

Production startup is integrated, not merely proposed. The server selects production composition when the activation resolver returns true and otherwise uses the development owner path ([server selection](/Users/youpele/DevWorld/bigbud/apps/server/src/server.ts#L292-L300)). The activation policy permits an environment override in local/source builds but prevents release bundles from honoring that override ([activation policy](/Users/youpele/DevWorld/bigbud/packages/shared/src/SshOwnerActivation.ts#L9-L18), [resolver](/Users/youpele/DevWorld/bigbud/packages/shared/src/SshOwnerActivation.ts#L34-L65)).

Production composition verifies/resolves the owner artifact, derives the profile binding, and records failures as typed closed admission rather than falling back. The boot path checks the backend lock, reads startup state, attaches or starts the owner, hydrates state, and opens admission only after those steps ([production composition](/Users/youpele/DevWorld/bigbud/apps/server/src/ssh/sshOwnerProductionComposition.ts#L136-L196), [boot sequence](/Users/youpele/DevWorld/bigbud/apps/server/src/ssh/sshOwnerProductionComposition.ts#L284-L347)).

This is an **opt-in local activation**, not an activated release. Legacy selection/executors remain, the release override is off, and the plan’s W7 legacy deletion/promotion change set has not occurred.
