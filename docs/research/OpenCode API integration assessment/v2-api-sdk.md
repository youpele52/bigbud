Research date: 2026-10-11. Scope: V2 only, except the V2 migration guide's explicit warning that V1 API integrations must migrate. No bigbud feature-by-feature mapping, no user service/API/credential/database calls, no application changes, no builds/tests executed. GitHub API responses were retrieved read-only with curl and parsed as JSON; source files were downloaded to approved temporary storage. ## 1. Is the V2 HTTP API/client as versatile and officially supported as the V2 embedded SDK?

### Takeaway

**For the generated public API operations, yes: the SDK is substantially the same client calling the same HTTP router in memory, not a separate richer session protocol. For host ownership, injecting JavaScript plugin definitions, runtime customization, and certain Effect-only direct service methods, no: embedding has additional capabilities that are not ordinary HTTP endpoints.** Both integration modes are documented first-party offerings, but this is not evidence of identical support commitments or of mature, frozen contracts. [Client guide](https://opencode.ai/v2/docs/build/client); [SDK guide](https://opencode.ai/v2/docs/build/sdk); [SDK Promise implementation](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/src/promise.ts#L25-L68); [SDK Effect implementation](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/src/effect/opencode.ts#L19-L67).

### Cited Findings

#### Official architecture and generated contract

- **[Docs] Explicit positioning.** Build intro offers both “Run it as a server” and “Embed it.” Its server option says: **“Connect to OpenCode with the same client used by the TUI and desktop app”**. This is strong first-party positioning for HTTP integration, not an unofficial workaround. [Build intro](https://opencode.ai/v2/docs/build/).
- **[Docs] Network client definition.** **“`@opencode/client` is the TypeScript client for the OpenCode HTTP API”** and **“Its native types and methods are generated from the same contract as the API reference.”** Promise and Effect entrypoints are documented; Effect returns typed Effects/Streams and decodes canonical schema values. [Client guide](https://opencode.ai/v2/docs/build/client); [Effect client guide](https://opencode.ai/v2/docs/build/client/effect).
- **[Docs] Embedded definition.** **“It assembles the OpenCode server and routes API calls through its HTTP router in memory. It opens no HTTP listener and adds no network hop.”** The guide says it **“exposes the full generated client”** and shares **“Promise values, declared errors, request options, and `AsyncIterable` streams”** with `@opencode/client`; `sessions` and `events` are convenience aliases. The Effect guide likewise says it shares schema values/errors/options/Streams with the network Effect client. [SDK guide](https://opencode.ai/v2/docs/build/sdk); [Effect SDK guide](https://opencode.ai/v2/docs/build/sdk/effect).
- **[Source, both requested pins] Not merely a marketing claim.** Promise SDK imports `OpenCode` from `@opencode/client`, calls **`OpenCode.make({ baseUrl: "http://opencode.local", fetch: host.fetch })`**, spreads `...client`, assigns `sessions: client.session` and `events: client.event`, and adds registration/close methods. The Promise implementation is byte-identical between these inspected release pins. [2.0.24 source](https://github.com/anomalyco/opencode/blob/e7a34f09bfd9134dfade5a8ddb843f7030bc9a69/packages/sdk/src/promise.ts#L25-L68); [2.0.26 source](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/src/promise.ts#L25-L68).
- **[Source, 2.0.26] Both hosts assemble the same route graph.** `createRoutes(...)` and `createEmbeddedRoutes(...)` both call `makeRoutes(...)`; embedded changes auth to no password and service URLs to empty, and can supply overrides/instance selection. Both use `HttpApiBuilder.layer(Api, { openapiPath: "/openapi.json" })` with the same handlers/middleware. The embedded host obtains `HttpRouter`, converts it with `HttpEffect.toWebHandlerWith`, and wraps it as an owned fetch. [Shared route assembly](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/server/src/routes.ts#L80-L114); [shared API handlers](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/server/src/routes.ts#L160-L190); [embedded web handler](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/src/internal/host.ts#L28-L66).
- \*_[Source, generation] Client generation compiles `ClientApi` from `@opencode/protocol/client`; Effect references canonical `@opencode/schema/_`types.`ClientApi`is constructed through the same protocol`makeDefaultApi` factory, with client-side middleware identities. Therefore “generated from the shared HttpApi/Protocol contract” is more exact than assuming every type is independently generated by reading the published OpenAPI JSON. [Generator](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/script/build.ts#L1-L42); [schema-aware output generation](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/script/build.ts#L86-L114); [ClientApi factory](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/src/client.ts#L18-L34).
- **[Test source, not executed] Deliberate anti-drift checks.** SDK `contract-identity.test.ts` checks **`Object.keys(ClientApi.groups)` equals `Object.keys(Api.groups)`**, then **`expect(emitPromise(client)).toEqual(emitPromise(server))`**. Client tests verify canonical schema object identity and composed generated output names. SDK transport tests check ambient fetch receives no embedded calls, streams/errors still work, and calls fail after scope closes. This establishes testing intent, not universal runtime proof or release guarantees. [SDK contract test](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/test/contract-identity.test.ts#L72-L100); [client contract test](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/test/contract-identity.test.ts#L11-L39); [transport test](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/test/transport.test.ts#L10-L63).

#### What is available over HTTP, and what “parity” must not imply

- **[Docs + source] Session data and control are HTTP features.** The API reference includes sessions/messages/context/inbox, create/update/remove/fork, prompt/command/synthetic/shell, interrupt/compact/wait, model/agent switching, forms, permissions, and event/log streams. These are generated client operations and hence present on the Promise embedded host too. Session creation/update accept `permissions` and application `metadata`. [API reference](https://opencode.ai/v2/docs/api); [create payload](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/src/groups/session.ts#L218-L239); [update payload](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/src/groups/session.ts#L359-L377).
- **[Source] Permissions are not SDK-only.** HTTP supports location pending requests, saved permissions list/removal, and session request create/list/get/reply; session create/update carry rulesets. Do not confuse this with registering server-side permission evaluation hooks. [Permission routes](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/src/groups/permission.ts#L21-L135); [session ruleset update](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/src/groups/session.ts#L359-L377); [plugin evaluation hook](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/plugin/src/promise/permission.ts#L7-L24).
- **[Source] Forms are not SDK-only.** Session form list/create/get/reply/cancel use native HTTP routes. Global/location pending forms use `/api/form`. [Session form routes](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/src/groups/session.ts#L793-L869); [API form reference](https://opencode.ai/v2/docs/api#form).
- **[Source + docs] Catalog visibility is not all-or-nothing.** HTTP lists agents, models/default model, providers, commands, skills, references, plugins, integrations, and MCP connection status. MCP resource/resource-template catalog is a native `GET /api/mcp/resource` endpoint. MCP add/remove/connect/disconnect are HTTP endpoints under `/api/experimental/mcp/*`; remove/connect overrides are explicitly runtime/until restart, not automatic durable config guarantees. [API reference](https://opencode.ai/v2/docs/api); [MCP routes and semantics](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/src/groups/mcp.ts#L8-L103).
- **[Docs + source] Tool registry and plugin durable data are a different boundary.** Plugins have `ctx.tool.list/transform/reload` and plugin-scoped `ctx.storage.get/set/remove/scan`. The current native API reference/OpenAPI has no general tool registry, tool callback registration, plugin storage, generic `data`, or workspace endpoint group. Those native groups are also absent from the pinned protocol assembly. The ordinary embedded Promise host spreads the same generated client; it does **not** magically expose `ctx.tool`/`ctx.storage` directly. Embedded application plugins can use these server-side capabilities; network integrations need a configured plugin with RPC for custom access. This is a statement about the inspected public surface, not proof that no internal implementation exists. [Plugin tool/storage docs](https://opencode.ai/v2/docs/build/plugins#tools); [plugin context fields](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/plugin/src/promise/plugin.ts#L26-L54); [storage interface](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/plugin/src/promise/storage.ts#L1-L9); [all protocol groups](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/src/api.ts#L159-L189); [published OpenAPI JSON](https://opencode.ai/v2/openapi.json).
- **[Docs] Plugins add powers beyond the native client.** Context is described as **“essentially an OpenCode server client”** but **“adds plugin-only methods for transforms, runtime hooks, reloads, registrations, and plugin options.”** Agent/provider/model/tool/command/MCP transforms and session/provider/tool hooks execute in the server; a client cannot upload a JavaScript callback as a native HTTP operation. [Plugin context and transforms](https://opencode.ai/v2/docs/build/plugins).
- **[Source] Native plugin routes are management, not executable registration.** `/api/plugin` lists; `/api/plugin/check` checks updates; `/api/plugin/update` updates package plugins. In contrast, embedded `opencode.plugin(plugin)` registers imported plugin values, and `CreateOptions.plugins` supports startup values. [Native plugin route definitions](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/src/groups/plugin.ts#L8-L60); [embedded registration](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/src/promise.ts#L20-L68); [SDK plugin store isolation](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/core/src/plugin/sdk.ts#L11-L39).
- **[Docs + source] HTTP can call installed plugin capabilities through RPC.** **“Once the RPC is registered, it can be called over HTTP or from another plugin.”** Typed `client.rpc(Acme)` or generic `POST /api/rpc/{rpcID}/{method}` transports `{input: ...}` to `{output: ...}`; contracts specify method input/output/errors and events. Crucial prerequisite: **“The server plugin must be configured and implement the RPC; importing a definition does not register it.”** This is extensibility, not a universal endpoint automatically exposing every internal method. [Plugin RPC guide](https://opencode.ai/v2/docs/build/plugins/rpc); [client RPC guide](https://opencode.ai/v2/docs/build/client#plugin-rpc); [generic route definition](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/src/groups/rpc.ts#L7-L30).
- **[Docs] RPC error/type contracts differ by facade, not embedding vs network.** Promise RPC accepts Standard Schema/JSON Schema definitions, leaves caught errors untyped, and does not run schema parsers locally; server parsing/transforms define output. Effect RPC supports typed declared-error channels, schema decoding, and Streams. Importing an Effect Schema RPC definition requires the Effect client. [Promise client RPC semantics](https://opencode.ai/v2/docs/build/client#plugin-rpc); [Effect client RPC semantics](https://opencode.ai/v2/docs/build/client/effect#plugin-rpc).
- **[Source] SDK Effect exceptions to simple alias parity.** Effect SDK interface omits/replaces `workspace`, adds direct `workspace.create/provision/destroy`, and overrides `sessions.create/get/move` with Core Session methods, while singular `session` remains generated. Promise SDK instead defines `sessions: OpenCodeClient["session"]` and has no such explicit workspace API. Thus the public docs' “aliases” simplification is exact for Promise but incomplete for the inspected Effect SDK. [Effect interface and implementation](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/src/effect/opencode.ts#L19-L67); [Promise interface](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/src/promise.ts#L25-L31).
- **[Source] “Full generated client” does not mean every transport operation.** Promise generation intentionally omits `pty.connect` and `persistentPty.connect`; Effect generation additionally omits `fs.read`/`fs.write`. These exclusions apply to the shared generated facades, not solely the network client. Native PTY connect is a WebSocket route in the API reference; lack of a generated connect wrapper is not absence of an HTTP/WS server feature. Do not promise an embedded no-listener host can use the network WebSocket URL identically without further verification. [Generator omit sets](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/src/client.ts#L69-L70); [PTY API reference](https://opencode.ai/v2/docs/api#pty).

### Inferences

- **Recommended architectural wording:** “V2's supported network integration is the HTTP API, optionally consumed through the first-party generated `@opencode/client` Promise/Effect facade. The V2 SDK embeds a server and largely reuses that facade; it is not the package for attaching to an existing server.” This inference follows the docs and actual construction path, not a claim that all internal Core services are HTTP-addressable. [Client guide](https://opencode.ai/v2/docs/build/client); [SDK construction](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/src/promise.ts#L33-L68).
- HTTP need not be less versatile for normal server-owned session/services functionality, because embedding and network share the operation contract. Embedding is more convenient for application-owned callbacks and custom runtime/service graphs. A server-side plugin with a designed RPC contract can bridge particular missing capabilities, but installing/trusting/maintaining that plugin is a separate requirement. [Shared route assembly](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/server/src/routes.ts#L80-L114); [RPC prerequisite](https://opencode.ai/v2/docs/build/client#plugin-rpc).

### Gaps

- No detailed V1 parity comparison is owned by this researcher. The official V2 migration guide explicitly calls server API/clients intentional breaking changes and says **“Use the `@opencode/client` package to access the released V2 API.”** This does not establish that every V1 endpoint or feature survived unchanged. [Migration guide, server API and clients](https://opencode.ai/v2/docs/migrate-v1#server-api-and-clients).
- No native arbitrary tool execution, MCP resource read, or remote plugin-storage API is established merely by seeing the tool registry/resource catalog. These need separate contract checks or plugin RPC, and must not be asserted from naming alone. [Published OpenAPI](https://opencode.ai/v2/openapi.json); [plugin RPC](https://opencode.ai/v2/docs/build/plugins/rpc).
- Live documentation/source discrepancy: current plugin guide shows `ctx.permission.rules({sessionID, permissions})`, but the inspected 2.0.26 and current V2 Promise plugin `PermissionDomain` only declares `list/get/reply` plus `hook`; HTTP session create/update is the verified ruleset route. Treat this snippet as unreliable until reconciled upstream, not as evidence of a special missing HTTP feature. [Docs permissions](https://opencode.ai/v2/docs/build/plugins#permissions); [2.0.26 type](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/plugin/src/promise/permission.ts#L22-L24); [current V2 type](https://github.com/anomalyco/opencode/blob/4617210822bdbb31e5749751afbfb4584ccedac8/packages/plugin/src/promise/permission.ts#L22-L24).

## 2. Does HTTP make more sense for an existing running service, and does it guarantee better long-term support?

### Takeaway

**For the stated existing-service/no-lifecycle-ownership scenario, the network client is the better architectural fit. Neither docs nor inspected code justify a guarantee of better future support, complete future feature exposure, patch/minor compatibility, or a support SLA.** Both surfaces are maintained first-party code; the public API explicitly remains described as experimental. [Client service guide](https://opencode.ai/v2/docs/build/client#local-background-service); [SDK ownership guide](https://opencode.ai/v2/docs/build/sdk#create-a-host); [API reference](https://opencode.ai/v2/docs/api).

### Cited Findings

#### Process, persistence, and platform ownership

- **[Docs] Client can attach without starting/stopping.** Main client entrypoints are **“browser-compatible and do not include local process management.”** Node-only service entrypoint offers **“`Service.discover()` returns a healthy registered endpoint without starting a process”**; `ensure()` may start a service; `stop()` stops the exact registered instance; `headers(endpoint)` supplies auth. Effect has the analogous Node-only service API. Existing-service integration should prefer explicit authenticated endpoint or discovery, not use `ensure`/`stop` merely because SDK examples mention lifecycle. [Promise service documentation](https://opencode.ai/v2/docs/build/client#local-background-service); [Effect service documentation](https://opencode.ai/v2/docs/build/client/effect#local-background-service).
- **[Docs + source] SDK owns a separate host.** `create()` returns an **“explicitly owned host”**; disposal releases router, Location services, fibers, and scoped plugins. It constructs `ManagedRuntime` and a database default **`{ path: ":memory:", ...server.database }`**. `CreateOptions` omits network host/port/password fields; it is not an attachment method. Persistent recovery needs explicitly configured `database.path`; the README says the default is memory. [Ownership docs](https://opencode.ai/v2/docs/build/sdk#create-a-host); [host options/default/runtime](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/src/internal/host.ts#L17-L46); [SDK persistence README](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/README.md#L70-L76).
- **[Source] Embedding also offers application-managed instance selection.** `instances.key`/`instances.configure` chooses plugin configurations by saved session metadata and current location. README explicitly says this **“is not an authorization or storage-isolation boundary.”** This is useful embedder machinery, not automatic remote server functionality or tenant isolation. [SDK option types](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/src/promise.ts#L9-L23); [instance lifetime/security scope](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/README.md#L61-L74).
- **[Source] Dependency footprint differs materially.** Client runtime manifest depends on schema/protocol packages; Effect and Solid are optional peers. SDK depends on client plus core/plugin/schema/server/util and Effect. Core includes native/platform-related PTY, watcher, filesystem search, image, and parser dependencies. This is evidence of a larger embedder runtime/dependency burden; it does not by itself prove failure on a given platform. [Client dependencies](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/package.json#L35-L50); [SDK dependencies](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/package.json#L30-L38); [Core dependencies](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/core/package.json#L97-L136).
- **[Source + test-script] Do not call SDK Bun-only.** Core has `bun`, `node`, and `workerd` runtime import conditions; Node SQLite uses `node:sqlite`, Node PTY requires `@lydell/node-pty`; SDK build targets Node ESM. Package verification script checks module imports using both Bun and Node, and separately bundles/boots Workerd. Those are positive support signals, not proof of a tested minimum Node version or complete OS matrix. [Runtime conditions](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/core/package.json#L32-L75); [Node SQLite](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/core/src/database/sqlite.node.ts#L1-L6); [Node PTY](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/core/src/pty/pty.node.ts#L1-L13); [SDK build](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/script/build.ts#L13-L22); [package verification script](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/script/verify-package.ts#L191-L235).
- **[Docs] Cloudflare is a distinct runtime profile, not universal native feature parity.** Guide says it uses Durable Object SQLite, persists durable events for eviction recovery, and **“replaces unavailable local filesystem and process services.”** Therefore the same API facade cannot guarantee identical filesystem/process capabilities across host profiles. [Cloudflare SDK guide](https://opencode.ai/v2/docs/build/sdk/cloudflare).

#### Support, maturity, versioning, and stream contract

- **[Docs + source] “Released” and “experimental” coexist.** V2 migration docs recommend the **“released V2 API”** through `@opencode/client`. API reference simultaneously says **“Experimental HttpApi surface for selected instance routes.”** Pinned protocol annotations have **`version: "0.0.1"`** and that same description; published OpenAPI JSON currently reports 142 operations, 118 paths, and `info.version` `0.0.1`. That metadata is not the installed server package version nor a compatibility promise. [Released API recommendation](https://opencode.ai/v2/docs/migrate-v1#server-api-and-clients); [current API reference](https://opencode.ai/v2/docs/api); [2.0.24 annotations](https://github.com/anomalyco/opencode/blob/e7a34f09bfd9134dfade5a8ddb843f7030bc9a69/packages/protocol/src/api.ts#L190-L198); [2.0.26 annotations](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/src/api.ts#L190-L198); [current OpenAPI JSON](https://opencode.ai/v2/openapi.json).
- **[Source] Generated outputs have a drift check.** Client manifest includes **`"check:generated": "bun run generate && git diff --exit-code -- src/promise/generated src/effect/generated src/effect/api"`**. This is a maintenance mechanism for source/contract synchronization, not a server-client version negotiation guarantee. [Client scripts](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/package.json#L28-L33).
- **[Source] Version matching is caller-selected, not enforced semver by default.** Service helper's `matchesVersion` says **`if (options.version === undefined) return true`**, then accepts a custom predicate or exact equality. Docs show `version.startsWith("2.")` as a user-supplied example; that does not establish that all 2.x contracts are compatible. [Matcher](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/service-version.ts#L1-L8); [service options docs](https://opencode.ai/v2/docs/build/client#local-background-service).
- **[Docs] Native/RPC events share a lazy, live-only connection.** **“Subscriptions are live-only, with no replay or automatic reconnection.”** Failure ends subscriptions; caller must subscribe again. Late subscriber gets `server.connected`, not past business events. Slow subscribers impose shared-source acceptance/backpressure unless buffered. RPC events arrive from all locations, so filter `event.location`. Effect docs state the same no retry/replay semantics. These are contract-level limitations regardless of whether the same facade is called in memory or remotely. ### Inferences

- Given the assignment's existing-service/no-lifecycle-ownership constraint, **attach using `@opencode/client` (or its Effect facade), preserving the service's authentication and location context.** Do not instantiate the embedded SDK merely to talk to that service: it creates its own router/runtime/database and requires ownership/disposal. The existing-service premise comes from the coordinator, not from inspecting bigbud code. [Client attach documentation](https://opencode.ai/v2/docs/build/client#create-a-client); [SDK construction/default DB](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/src/internal/host.ts#L28-L46).
- Prefer the official generated network facade to hand-written HTTP when compatible with the application's dependency constraints: it reuses first-party types, error semantics, streaming, and RPC contract helpers without taking server lifecycle ownership. Raw HTTP/OpenAPI tooling remains legitimate, especially for other languages or explicit transport control; neither approach guarantees additional backend feature support. [Client generation and custom fetch](https://opencode.ai/v2/docs/build/client); [raw API/OpenAPI reference](https://opencode.ai/v2/docs/api).
- **Do not sell API adoption as “guaranteed better supported.”** Stronger justified claim: it is the officially documented boundary used for independent clients and better matches an existing server's ownership model. Both SDK and client ride the same evolving API contract, and the SDK additionally couples the application to server/Core/runtime dependencies. [Build positioning](https://opencode.ai/v2/docs/build/); [experimental contract annotation](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/src/api.ts#L190-L198); [SDK dependencies](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/package.json#L30-L38).
- Reliability requires client-specific reconnect/resubscribe/reconcile logic and explicit version policy. Avoid treating a shared-schema identity test, a major-version predicate, “released,” or first-party usage as an assurance that failures, replay, future additions, or incompatible upgrades are handled automatically. [Live-only stream docs](https://opencode.ai/v2/docs/build/client#stream-events); [caller version matcher](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/service-version.ts#L1-L8).
