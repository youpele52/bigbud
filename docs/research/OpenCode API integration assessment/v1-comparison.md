# OpenCode V1 SDK expectations and V2 network-client migration

## Was the V1 SDK an embedded runtime, and is V2's API intrinsically less capable?

### Takeaway

No: the V1 `@opencode-ai/sdk` was already a generated HTTP/SSE client, with an optional wrapper that launched the `opencode` executable. The released V2 replacement for that integration is `@opencode/client`; V2's **actual embedded runtime** is the separate `@opencode/sdk`, not the old package with its name changed.

### Cited Findings

- **Version scope:** bigbud declares `@opencode-ai/sdk: ^1.17.13` and its lockfile resolves **1.17.13**. The official tag resolves to commit **`10c894bdeef3618f5666fb506ef7f9491bb964d8`**. This is the comparison baseline, not a guessed older API. Local evidence: `apps/server/package.json:37`, `bun.lock:850`; upstream [tag API](https://api.github.com/repos/anomalyco/opencode/git/ref/tags/v1.17.13), [pinned package exports/version](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/package.json).
- **Naming trap:** the V1 package explicitly exports `./v2`. Therefore bigbud's `import ... from "@opencode-ai/sdk/v2"` does **not** identify the released OpenCode 2 client. At that release the main generated client's `session` getter is `Session2`, whose URLs remain `/session/...`; it also exposes a separate transitional `v2` group. Do not substitute either for the released `@opencode/client` contract. [V1 package exports](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/package.json), [main client's session and v2 getters, lines 7195–7217](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/gen/sdk.gen.ts#L7195-L7217).
- V1 `createOpencode()` first calls `createOpencodeServer()`, then `createOpencodeClient({ baseUrl: server.url })`, returning `{client, server}`. The wrapper does not execute the agent in the caller's JS runtime. [Exact source, lines 10–23](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/index.ts#L10-L23).
- V1 `createOpencodeServer()` launches a child executable with `serve --hostname=... --port=...`, passes inline config via `OPENCODE_CONFIG_CONTENT`, waits for `"opencode server listening"`, and closes by stopping that process. Defaults are loopback, port 4096, startup timeout 5000ms. [Exact source, lines 22–99](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/server.ts#L22-L99).
- V1 client-only construction creates a generated HTTP client and returns a generated `OpencodeClient`. It also injects directory/workspace routing and interceptors; an HTML response triggers `"Request is not supported by this version of OpenCode Server"`. This is explicit evidence that the executable/server contract, not merely npm installation, determines operation support. [Exact source, lines 50–93](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/client.ts#L50-L93).
- The official V1 SDK page calls itself **"Type-safe JS client for opencode server"**, says all API types are generated from OpenAPI, and exposes `responseStyle` plus `throwOnError` (default false). This page is rolling V1 documentation; pinned source above controls release-specific claims. [V1 SDK docs](https://opencode.ai/docs/sdk/).
- V2's client guide states `@opencode/client` methods/types are **"generated from the same contract as the API reference"**. Its standard client is browser-compatible; local process management is separately available through `@opencode/client/service`. [V2 client docs](https://opencode.ai/v2/docs/build/client), [pinned guide](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/services/www/src/docs/content/build/client/index.mdx#L138-L178).
- V2 `@opencode/sdk` is genuinely embedded: **"routes API calls through its HTTP router in memory"**, **"opens no HTTP listener"**, exposes the full generated client and aliases `sessions`/`events`, and owns scoped resources requiring `close()`/`await using`. It adds host/plugin integration, not a separate richer ordinary session HTTP contract. [V2 SDK docs](https://opencode.ai/v2/docs/build/sdk), [pinned embedded host source, lines 28–66](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/src/internal/host.ts#L28-L66).
- The inspected embedded host defaults its database to `:memory:` unless server database options override it. Do not assume SDK-host persistence/lifetime equals the installed service's persistence/lifetime. [Host source, lines 32–45](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/sdk/src/internal/host.ts#L32-L45).

### Inferences

- For an external orchestration service such as bigbud, switching from the old SDK to the V2 network client is a **new API contract migration**, not a downgrade from embedded execution to HTTP. The ordinary V2 SDK and network client share the generated contract; network/process ownership is the meaningful deployment choice. [V1 wrapper](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/index.ts#L10-L23), [V2 SDK guide](https://opencode.ai/v2/docs/build/sdk).
- Prefer the released V2 network client for an application that already separates UI/orchestration from the provider service. Consider the embedded SDK only for an explicit requirement to own OpenCode inside the application process, avoid an HTTP listener, or register host-local plugins. This is architectural judgment, not a measured performance claim. [Client guide](https://opencode.ai/v2/docs/build/client), [SDK guide](https://opencode.ai/v2/docs/build/sdk).

### Gaps

- No latency, memory, throughput, or fault-isolation benchmark was run. The absence of a network hop does not by itself prove that embedding is a better overall deployment.
- This assignment inspected legacy imports/version and wrapper behavior, not the complete bigbud service mapping; that belongs to the sibling research scope.

## Which V1 behaviors survive, and which require semantic migration rather than renaming?

### Takeaway

V2 exposes the main integration capabilities—sessions, prompts, streaming, permissions, interactive input, model/provider catalogs, MCP, forks/reverts, metadata—but the payloads and lifecycle semantics change materially. Feature presence is not a promise of one-to-one behavioral compatibility.

### Cited Findings

- **Official compatibility boundary:** the migration guide says **three** intentional breaking changes: plugin API; server API/clients; terminal configuration. It explicitly says integrations calling the V1 API **"must migrate to the V2 API"** and directs them to `@opencode/client`. Supported V1 configuration/file definitions are intended to remain compatible; this does not extend to V1 HTTP clients. [Pinned migration guide, lines 8–23](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/services/www/src/docs/content/migrate-v1.mdx#L8-L23), [lines 561–573](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/services/www/src/docs/content/migrate-v1.mdx#L561-L573).
- **Session ownership/location/metadata:** V1 `Session` includes `id`, `parentID`, `projectID`, `directory`, optional `metadata`, `permission`, and `version`. V2 `SessionInfo` still has `id`, `parentID`, `projectID`, model, metadata, permissions, and revert; now it has `location`, `subpath`, fork-boundary information, token/cost totals, and outcome. V2 metadata is JSON-valued, not arbitrary JS values. [V1 type, lines 170–219](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/gen/types.gen.ts#L170-L219), [V2 type, lines 1998–2015](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L1998-L2015), [V2 JSON metadata, lines 1–50](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L1-L50).
- **Creation/correlation:** V2 creation accepts caller `id`, `parentID`, `location`, model, metadata, and permissions, so upstream session IDs and integration metadata remain first-class. V2 session list is a paginated `{data, cursor}` response, not the old bare session array expectation. [Creation implementation, lines 577–597](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/client.ts#L577-L597), [list types, lines 2269–2275](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L2269-L2275).
- **Prompt semantics:** V1 has `promptAsync`, explicitly **"returning immediately"**, and sends `parts`, model `{providerID, modelID}`, agent, system, variant, noReply/tools/format. V2's ordinary `prompt` accepts `text`, files/agents/skills, metadata, delivery (`steer`/`queue`) and resume; its result is `SessionInboxUser`, **not a completed assistant reply**. Model/agent have dedicated session-switch methods. A V1 prompt await cannot simply be interpreted as V2 turn completion. [V1 promptAsync, lines 4090–4143](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/gen/sdk.gen.ts#L4090-L4143), [V2 prompt implementation, lines 715–736](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/client.ts#L715-L736), [V2 output type, line 4332](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L4332), [switch operations, lines 667–690](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/client.ts#L667-L690).
- **Interrupt/completion:** V1 `session.abort` stops ongoing processing via `/session/{sessionID}/abort`. V2 exposes `session.interrupt` at `/api/session/{sessionID}/interrupt`, a `{interrupted:boolean}` result, and explicit execution success/failure/interrupted/status/idle events. Treat completion as a state/event reconciliation problem, not a method-name substitution. [V1 abort, lines 3908–3937](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/gen/sdk.gen.ts#L3908-L3937), [V2 interrupt, lines 978–989](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/client.ts#L978-L989), [V2 execution event types, lines 666–705](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L666-L705).
- **Streaming payloads:** V1 generated SSE returns `{stream}`; legacy message deltas use `properties.sessionID/messageID/partID/field/delta`. V2 public client subscriptions are direct async iterables, with events such as `session.text.delta` carrying `data.sessionID/assistantMessageID/ordinal/delta` and optional location. Event mapping needs rewritten discriminants/payload parsing and session filtering. [V1 SSE result, lines 74–76](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/gen/core/serverSentEvents.gen.ts#L74-L76), [V1 delta, lines 6650–6659](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/gen/types.gen.ts#L6650-L6659), [V2 delta, lines 941–947](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L941-L947), [V2 client guide](https://opencode.ai/v2/docs/build/client).
- **Permissions remain supported:** V1 asks with `permission`/`patterns`/`always` and replies using `requestID` plus `reply`. V2 asks with `action`/`resources`/`save`, source metadata, and `sessionID`; replying requires `sessionID`, `requestID`, and `decision: once|always|reject`. V2 provides pending-request listing and saved-permission APIs. This is changed shape/scope, not removal. [V1 request/reply events, lines 6854–6880](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/gen/types.gen.ts#L6854-L6880), [V2 request, lines 1551–1566](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L1551-L1566), [V2 reply input, lines 6158–6171](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L6158-L6171), [V2 generated operations, lines 1512–1606](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/client.ts#L1512-L1606).
- **Questions become forms, not a verified regression:** V1 exposes `question.list/reply/reject`, answering arrays of strings. V2 exposes global pending forms plus per-session form list/create/get/reply/cancel, with keyed typed field answers (string/number/boolean/string arrays). The absence of a V2 `question` group is not evidence that interactive input disappeared. Exact V1 UI-equivalent mapping must still be tested. [V1 question methods, lines 2982–3083](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/gen/sdk.gen.ts#L2982-L3083), [V2 form reply/cancel, lines 5512–5528](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L5512-L5528), [V2 form schemas, lines 1906–1934](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L1906-L1934), [V2 HTTP contract](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/openapi.json).
- **Fork/revert survive but differ:** V1 fork takes optional `messageID`, revert takes message/part ID and unrevert restores. V2 fork accepts optional `before`; recorded fork metadata explicitly identifies `before`/`through` boundaries. Revert is staged, cleared, then committed; stage accepts message ID and whether to include files. Commit/clear return void. Preserve the staged lifecycle rather than calling a nonexistent old `unrevert`. [V1 fork, lines 3870–3905](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/gen/sdk.gen.ts#L3870-L3905), [V1 revert/unrevert, lines 4256–4326](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/gen/sdk.gen.ts#L4256-L4326), [V2 fork, lines 4102–4107](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L4102-L4107), [boundary schema, line 39](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L39), [V2 revert, lines 821–856](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/client.ts#L821-L856).
- **Provider/model catalog is reorganized:** V1 `provider.list` returns `{all, default, connected}`. V2 separately exposes provider list/get, model list/default, integration connection operations, and credentials. V2 list results include location and data. A legacy connected-provider discovery implementation cannot reuse the V1 response parser. [V1 response, lines 9315–9325](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/gen/types.gen.ts#L9315-L9325), [V2 provider/model result types, lines 5622–5660](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L5622-L5660), [V2 generated contract](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/openapi.json).
- **MCP remains available:** V1 has status/dynamic add. V2 has `mcp.list` and MCP resource catalog, plus add/remove/connect/disconnect under **experimental** HTTP paths, location-scoped. Config normalizes supported V1 entries into V2 `mcp.servers`; native config separates catalog/execution timeouts and changes enabled to disabled. Do not claim identical stability for MCP read APIs and dynamic MCP mutations. [V1 methods, lines 2394–2437](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/gen/sdk.gen.ts#L2394-L2437), [V2 methods, lines 1339–1414](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/client.ts#L1339-L1414), [migration guide MCP section](https://opencode.ai/v2/docs/migrate-v1#mcp-servers).
- **Real documented capability difference:** V2 preserves `lsp` config but **"does not run language servers, expose LSP tools, or produce LSP diagnostics"**. Therefore blanket V1/V2 feature parity is false even though major integration domains exist. [Pinned guide, lines 415–416](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/services/www/src/docs/content/migrate-v1.mdx#L415-L416).
- **History migration is separate from API migration:** the released protocol has an experimental V1 migration-status endpoint described as **"progress of the V1 to V2 session history migration"**. This verifies that a migration facility exists, but not blanket preservation of all old session IDs/permissions/metadata. [Exact protocol source, lines 10–24](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/src/groups/migration.ts#L10-L24).

### Inferences

- A compatibility adapter should normalize session IDs, location, metadata, permission/form events, prompt admission versus completion, message pagination, and staged revert behavior. Mere package-name replacement is insufficient. [Official API break](https://opencode.ai/v2/docs/migrate-v1#server-api-and-clients), [released contract](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/openapi.json).
- V2's explicit inbox, execution outcomes, metadata and location afford richer service coordination than the old prompt-only assumptions, but feature-fit is not proof of production reliability or total parity. [Session types](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L1998-L2015), [inbox/prompt types](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L2213-L2281).

### Gaps

- No live native service calls or session migrations were performed. ID retention, saved approval migration, custom metadata preservation, forked-session execution, and MCP authentication compatibility need isolated fixtures against the selected V2 executable.
- No exhaustive old SDK operation parity table was attempted. Share, legacy TUI, LSP, sync, and plugin-only internals should not be presumed portable just because a similar API group exists.

## What maturity and network-reliability guarantees should a migration rely on?

### Takeaway

Use pinned released V2 client/server contracts and explicit version/capability checks; do not describe all of V2 as backward-compatible with the V1 SDK. Streaming recovery is especially important: V2 documents live-only subscriptions with **no replay or automatic reconnect**, while the old generated transport did retry failed connections.

### Cited Findings

- **Release pins:** V2 assessment reads **2.0.26**, commit **`9b4ec5714d481559990db0a816d5dec19541a814`**; minimum comparison reads **2.0.24**, commit **`e7a34f09bfd9134dfade5a8ddb843f7030bc9a69`**. The client package at 2.0.26 is `@opencode/client`, version `2.0.26`, with Promise, Effect, and service exports. [2.0.26 package](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/package.json), [2.0.24 protocol](https://github.com/anomalyco/opencode/blob/e7a34f09bfd9134dfade5a8ddb843f7030bc9a69/packages/protocol/openapi.json), [2.0.26 protocol](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/openapi.json).
- An offline structural comparison of those two pinned protocol JSON files found **no added/removed HTTP methods/paths/operation IDs and no schema changes**; the only document difference was the `/api/fs/read/*` description gaining HTTP-cache/range detail. This is narrow observed stability over two releases, not a future compatibility guarantee. [2.0.24 contract](https://github.com/anomalyco/opencode/blob/e7a34f09bfd9134dfade5a8ddb843f7030bc9a69/packages/protocol/openapi.json), [2.0.26 contract](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/openapi.json).
- **V1 retries:** generated transport retries network/parsing failures with exponential backoff (default 3s, capped 30s), configurable attempt count; it tracks SSE IDs and can send `Last-Event-ID`. Normal EOF ends the stream. This mechanism alone does not prove the V1 server supplied durable replay. [Retry options/loop, lines 35–112](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/gen/core/serverSentEvents.gen.ts#L35-L112), [failure retry versus normal completion, lines 220–232](https://github.com/anomalyco/opencode/blob/10c894bdeef3618f5666fb506ef7f9491bb964d8/packages/sdk/js/src/v2/gen/core/serverSentEvents.gen.ts#L220-L232).
- **V2 explicit guarantee:** **"Subscriptions are live-only, with no replay or automatic reconnection. A source failure ends current subscriptions; subscribe again after recovery."** Late subscribers receive current `server.connected`, not past business events. Shared subscriptions are lazy, one source per client, subscriber-local cancellation; last subscriber closes the source. [Pinned guide, lines 68–76](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/services/www/src/docs/content/build/client/index.mdx#L68-L76), [source, lines 24–57 and 105–115](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/shared-events.ts#L24-L57).
- **Important source/documentation mismatch:** the pinned guide says the shared source **"waits for active subscribers to accept each event"**. However pinned 2.0.26 Promise `SharedEvents` fanout uses per-subscriber queues with capacity **4096**, ending an overflowing subscriber with `"Event subscriber exceeded its 4096-event capacity"`; it does not await every consumer's work. Do not advertise lossless unbounded backpressure based only on the prose. Both sources advise a fast-consumption/buffering design, but exact overflow behavior needs version-pinned tests. [Guide, lines 68–76](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/services/www/src/docs/content/build/client/index.mdx#L68-L76), [implementation, lines 24–25 and 85–102](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/shared-events.ts#L85-L102).
- V2 has an experimental per-session log stream with `after` and `follow`, distinct from live event subscription. It is a possible recovery primitive, not proof that ordinary event.subscribe replays or that every transient text delta is durable. [Generated log operation, lines 966–977](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/client.ts#L966-L977), [durable-event/log types, lines 2379–2530](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L2379-L2530).
- **Lifecycle/version policy:** Node `Service.discover` finds without starting, `Service.ensure` finds or starts, `Service.stop` stops the exact registered instance, and `Service.headers` supplies auth. `ensure` supports exact version or a predicate; the implementation's matcher returns true when no version option is supplied. The example `startsWith("2.")` is user-selected compatibility policy, not protocol certification. [Pinned client guide, lines 138–178](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/services/www/src/docs/content/build/client/index.mdx#L138-L178), [matcher source, lines 3–7](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/service-version.ts#L3-L7).
- **Version/maturity terminology:** server info exposes `version`, PID, URLs and optional capabilities, not an advertised universal `modelVersion` protocol-negotiation field. `ModelInfo` has `status: alpha|beta|deprecated|active`, released time, capabilities, limits, variants and enabled state. Those statuses describe **models**, not maturity of the entire V2 API. No `modelVersion` identifier was found in the inspected V1/V2 generated client types. [ServerInfo/ModelRef, lines 3–19](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L3-L19), [ModelInfo, lines 1953–1971](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/types.ts#L1953-L1971).
- **Experimental surfaces:** dynamic MCP mutations, per-session logs, import/export, wait, global config updates, and various terminal APIs use `/api/experimental/...`. Their presence in generated clients is not a published promise of the same long-term stability as ordinary resources. [Pinned generated operations](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/client.ts), [pinned protocol](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/protocol/openapi.json).
- Context7 was resolved and queried using the **V2-specific** library `/websites/opencode_ai_v2`; it corroborated the new server/client contract and migration boundary. A separate resolved `opencode-sdk-js` library describes a REST client and must not be silently treated as V2 `@opencode/sdk` documentation. Primary pinned source and official V2 docs above control the findings. [Official migration guide](https://opencode.ai/v2/docs/migrate-v1), [V2 client guide](https://opencode.ai/v2/docs/build/client).

### Inferences

- A production migration should explicitly resubscribe after failures, re-fetch authoritative session/messages/forms/permissions, deduplicate durable events where applicable, and isolate slow downstream work from event iteration. Use experimental session-log replay only behind version-pinned recovery tests. [Subscription guarantees](https://opencode.ai/v2/docs/build/client#stream-events), [session log operation](https://github.com/anomalyco/opencode/blob/9b4ec5714d481559990db0a816d5dec19541a814/packages/client/src/promise/generated/client.ts#L966-L977).
- Pin the V2 client/executable to tested releases (at minimum test both required 2.0.24 and selected 2.0.26) rather than accepting any `2.*` as proven compatible. Keep V1 behavior behind an explicitly legacy adapter if it must remain available; do not drive V2 with old SDK assumptions. [Required API migration](https://opencode.ai/v2/docs/migrate-v1#server-api-and-clients), [version policy hook](https://opencode.ai/v2/docs/build/client#local-background-service).

### Gaps

- No public guarantee of indefinite backwards compatibility, enterprise SLA, exactly-once event delivery, or automatic stream replay was established. Do not imply such guarantees.
- The 4096-queue discrepancy is verified by inspection, not a runtime overload test. Effect-client streaming may have different implementation details and needs separate verification.
- `modelVersion` may refer to terminology in another integration or user discussion; no such public field was found in the inspected generated contracts. Clarify before assuming it is a supported handshake mechanism.
- This was read-only research: no native service/account/config/database calls, app edits, tests, worktrees, or commits were performed. Only this requested research note was authored.
