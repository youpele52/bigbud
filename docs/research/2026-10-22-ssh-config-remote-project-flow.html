Add SSH remote project: two ways to connect, same options after that

A switch at the top picks how bigbud finds the machine. It does not change how bigbud works with it: Connection method and Provider runtime always appear, in the same place and with the same defaults, in both modes. Blue dashed boxes are shared; grey dashed boxes appear in only one mode.

What changes and what doesn't

Area Change
Stored project / target ID No change. Config mode stores host=<alias> and leaves user, port and key empty, exactly like typing the alias by hand today. Existing projects are untouched.
Verification, agent install, project creation No change. Both modes call the same functions.
Connection method / Provider runtime One shared component placed after the mode-specific fields in both modes. Direct SSH is now listed first and preselected for new projects (createDefaultRemoteProjectDraft changes remoteTransport from "agent" to "direct-ssh"). Existing projects keep the transport stored in their target ID.
Dialog New mode switch, alias picker, and an Advanced section in config mode. The draft gains connectionSource: "manual" | "ssh-config", which lives in the UI only and is never stored.
Switching modes Shared fields (path, name, connection method, runtime) carry over. Host fields are kept separately per mode, so switching back doesn't lose what you typed.
Edit existing project Opens in config mode if the host matches a discovered alias and has no overrides; otherwise opens in manual mode. Nothing extra is stored.
Server New read-only server.listSshConfigHosts RPC plus a parser in apps/server/src/ssh/.
