# Goose: what happens to a turn cut by sleep or network loss

Research date: 2026-10-22. Sources: aaif-goose/goose (formerly block/goose) at b89ab56 (2026-10-22), latest release v1.55.0 (2026-10-16). Paths are relative to the repo root. Tags: **[V]** verified in source at that commit, **[D]** from the repo's docs, **[I]** inferred.

## Answer

Goose never continues a cut turn by itself. A network error that survives the provider's request retry (3 retries, 1 s doubling to 30 s, with jitter) becomes an error message saved in the session, and the turn ends. Retry wraps only the opening HTTP request, not a stream that dies halfway. The useful part for bigbud is the shape of the agent loop: every step re-reads the conversation from SQLite and writes its result back before the next step, so the assistant message that asks for a tool is saved before the tool runs, and tool results are saved only after the whole batch finishes. After a cancellation Goose closes every unanswered tool request with the synthetic result "Tool call was interrupted before completing", and a fresh process will not rerun a model-issued tool call; it answers it with an "approval expired, request the tool again" error instead. The desktop app listens for Electron `resume`, but only to reconnect its UI socket.

## What happens when the connection is cut mid-turn

- **Request start.** Providers wrap the HTTP call that opens the stream in `with_retry`. Defaults: `max_retries` 3, initial 1000 ms, multiplier 2.0, cap 30 000 ms, jitter 0.8 to 1.2. Rate-limit, server and network errors retry; 4xx retries unless `transient_only` or a known permanent message. A `Retry-After` delay is used as is. [V: [retry.rs#L14-L17](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-provider-types/src/retry.rs#L14-L17), [#L71-L87](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-provider-types/src/retry.rs#L71-L87), [#L107-L157](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-provider-types/src/retry.rs#L107-L157); Anthropic example [anthropic.rs#L184-L201](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-providers/src/anthropic.rs#L184-L201)]
- **Mid-stream.** Inside the inference step, an `Err` from the stream calls `error_outcome`: it builds a message from the provider error and returns it as the step result together with whatever chunks were already accumulated. There is no retry here. [V: [inference.rs#L384-L396](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-agent/src/inference.rs#L384-L396), [#L522-L526](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-agent/src/inference.rs#L522-L526)]
- **Turn end.** An error left as the last message stops further inference and ends the turn. [V: [ops_exit_on_error.rs#L1-L18](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose/src/agents/state_machine/ops_exit_on_error.rs#L1-L18); `applies` checks `trailing_error`, [inference.rs#L419-L424](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-agent/src/inference.rs#L419-L424)]
- **Hung socket after wake.** The HTTP client has a 30 s connect timeout and a 600 s read timeout. A connection that went silent across sleep without a reset can wait up to 10 minutes before it fails. [V: [api_client.rs#L19-L20](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-providers/src/api_client.rs#L19-L20), [#L314-L318](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-providers/src/api_client.rs#L314-L318)]
- **Empty responses** are retried up to 3 times in the inference step. This is the only automatic re-ask of the model. [V: [inference.rs#L78](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-agent/src/inference.rs#L78), [#L551-L572](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-agent/src/inference.rs#L553-L572)]
- **Sleep awareness.** None in the Rust agent or providers; a search for suspend or wake handling found nothing. [V by search, I for completeness] The Electron main process forwards `powerMonitor` `resume` to every window as `system-resume`, and the renderer closes and reopens its ACP WebSocket to the local `goose serve` process with jittered backoff from 500 ms to 30 s. [V: [main.ts#L2414-L2421](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/ui/desktop/src/main.ts#L2414-L2421), [App.tsx#L436-L440](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/ui/desktop/src/App.tsx#L436-L440), [acpConnection.ts#L27-L29](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/ui/desktop/src/acp/acpConnection.ts#L27-L29), [#L72-L92](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/ui/desktop/src/acp/acpConnection.ts#L72-L92)]

## In-flight tool calls

- **Order.** The state machine loop is load session, run one step, apply its effects to SQLite, repeat. The model's assistant message with tool requests is therefore saved before any tool runs. [V: [machine.rs#L215-L229](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-agent/src/machine.rs#L215-L229); effect writer [session.rs#L53-L73](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose/src/agents/state_machine/session.rs#L53-L73)]
- **Results are saved per batch.** All tool calls of one assistant message run concurrently; their results are collected and saved as one user message only after the last one finishes. A crash in the middle loses the results of the tools that did finish. [V: [ops_toolcalling.rs#L1069-L1107](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose/src/agents/state_machine/ops_toolcalling.rs#L1069-L1107)]
- **Cancellation repair.** On cancel, `finalize` saves the partial batch, then adds one user message with the error result "Tool call was interrupted before completing" for every request in the current turn that has no response. [V: [machine.rs#L73-L96](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-agent/src/machine.rs#L73-L96), [#L232-L268](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-agent/src/machine.rs#L232-L268)]
- **Error repair.** When the turn fails with an error instead, `run` returns before `finalize`, so the unanswered request stays in SQLite. [V: [machine.rs#L215-L229](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-agent/src/machine.rs#L215-L229)] Before every model call, `fix_conversation` removes tool requests that have no response and responses that have no request, from the copy sent to the provider only. It does not invent a result. [V: [conversation.rs#L233-L294](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-provider-types/src/conversation.rs#L233-L294), [#L426-L512](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-provider-types/src/conversation.rs#L426-L512); caller [inference.rs#L479-L486](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-agent/src/inference.rs#L479-L486)]
- **No blind re-execution.** A pending request in the current turn runs only if this process holds an extension lease for it. Without one, which is the case in a fresh process, each pending model-issued request is answered with "Tool approval expired because its extension lease is no longer available. Request the tool again." [V: [ops_toolcalling.rs#L30-L31](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose/src/agents/state_machine/ops_toolcalling.rs#L30-L31), [#L910-L968](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose/src/agents/state_machine/ops_toolcalling.rs#L910-L968)]
- **CLI.** On a stream error the CLI answers trailing tool requests with "An uncaught error happened during tool use" and prints that the error is often connection related and that you may be able to continue. It does this in its in-memory list (`push_message` is a `Vec` push); I did not find it written to SQLite. [V: [mod.rs#L1530-L1546](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-cli/src/session/mod.rs#L1530-L1546), [#L1683-L1750](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-cli/src/session/mod.rs#L1683-L1750), [#L2044-L2046](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-cli/src/session/mod.rs#L2044-L2046)]

## What is persisted, and when

- **Store.** SQLite `sessions.db`, WAL mode, 30 s busy timeout, one row per message (`content_json`, `metadata_json`). The older JSONL session files are imported once as legacy. [V: [session_manager.rs#L34](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose/src/session/session_manager.rs#L34), [#L1052-L1071](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose/src/session/session_manager.rs#L1052-L1071), [#L1182-L1196](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose/src/session/session_manager.rs#L1182-L1196), [#L1262](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose/src/session/session_manager.rs#L1262)]
- **User prompt** is saved before the turn starts. [V: [agent.rs#L761-L763](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose/src/agents/agent.rs#L761-L763)]
- **Model output** is saved when the inference step returns, not per chunk. A process killed mid-stream loses the partial answer. [V: chunks go to an accumulator, [inference.rs#L527-L547](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-agent/src/inference.rs#L527-L547)]
- **Tool approval requests** are saved before they are shown, because a reply can arrive at once. [V: [session.rs#L143-L149](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose/src/agents/state_machine/session.rs#L143-L149)]

## What the user sees

- **Resume.** `goose session --resume` loads the saved conversation and waits for input. It does not continue a cut turn. [D: `documentation/docs/guides/goose-cli-commands.md:208`; V: no continuation in [builder.rs#L707-L709](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-cli/src/session/builder.rs#L707-L709)]
- **ACP load.** When a client loads a session, the server replays history, and restarts a turn only if a tool approval is pending or answered but not yet applied, and only if no run for that session is already active. [V: [load_session.rs#L413-L466](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose/src/acp/server/load_session.rs#L413-L466), [agent.rs#L815-L834](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose/src/agents/agent.rs#L815-L834)]
- **Run lifetime.** A prompt run is registered per session and guarded by a drop guard that cancels it if the request future is dropped, "e.g. the roaming connection carrying it is revoked or lost". [V: [server.rs#L2286-L2310](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose/src/acp/server.rs#L2286-L2310)]

## Retry limits and parking

- Provider request: 3 retries by default, configurable per provider by environment variables (Bedrock defaults to 6). [V: retry.rs above; D: `documentation/docs/guides/environment-variables.md:92-116`]
- One credential refresh on an auth error, separate from the retry count. [V: [retry.rs#L206-L230](https://github.com/aaif-goose/goose/blob/b89ab563a034ab9ff323a916fd1aef7be6ea8d67/crates/goose-provider-types/src/retry.rs#L206-L230)]
- No turn-level retry, no parked state, no Retry button. The error message is the end state.

## For bigbud

- **Adds to D4 (TypeScript).** Goose's "step reads persisted state, writes its result, then the next step reads again" loop makes "a tool may be mid-flight" a pure function of the transcript: an assistant tool request with no saved response. bigbud's classifier can use the same rule on its own projection.
- **Adds to D4 (TypeScript).** Answer a stale tool request with an explicit error result that tells the model to request it again, rather than dropping it or rerunning it. Goose does this when no live lease exists. This fits the "ask the user" branch: the user's answer can become that result.
- **Confirms D1.** Goose saves the tool request before running the tool, but has no `may-have-been-sent` state for the model request itself and loses partial output on a crash. bigbud's attempt states fill that gap.
- **Adds to D3.** A 600 s read timeout means a dead stream after wake can look alive for 10 minutes. bigbud should not wait for the provider to time out; the wake signal should start reconciliation, and a stall watchdog should cover the case where no error ever arrives.
- **Contradicts nothing in D2, but differs.** Goose routes `resume` main to renderer and only reconnects the UI socket; the agent process gets no hint. bigbud's choice to send it straight to the server is the stronger design.
- **Adds to D5.** Goose has no parking; a failed turn is just an error row. Nothing to copy.
- **Adds to D8 (Rust).** The agent loop, retry and repair are Rust, but sleep handling lives in Electron TypeScript. The same split as bigbud's D8.
