# Server-owned native Inyosira scheduling

The authoritative server launches one dedicated `bigbud-desktop-supervisor --thread-organization` child using the existing packaged native binary. Rust owns deterministic attention, activity, snooze, idle, older-thread and global Present-target decisions from compact versioned facts. TypeScript retains database ownership, canonical command authorization, final acceptance checks and transactional event/receipt persistence. This narrowly extends the systems supervisor to derived scheduling proposals without granting it independent domain truth or provider-protocol interpretation.

A dedicated mode isolates scheduling backpressure and failure from desktop delivery. It works headlessly and does not depend on an Electron window or delivery enable flag. Putting scheduling in the remote agent would cross the workspace capability boundary; sharing the delivery process would couple stalls; an in-process native binding would lose crash containment. No new crate or dependency is required.

The production reactor starts only the native bridge. A failed, stale or missing child fences automatic acceptance, resynchronises within bounded attempts, and then pauses automation; it never switches to a TypeScript scheduler. Manual organisation remains available. Native generations are fenced before shutdown waits. Compact snapshots and contiguous ordered facts establish admission; unknown activity protects cleanup, while durable prepared operations and canonical receipts reconcile ambiguous acknowledgements.

This decision records the approved boundary. Cross-platform artifact qualification and the independent final review remain release acceptance gates; local process tests do not establish those gates.
