# Provider Integration Checklist

Date: 2026-10-20

## Purpose and completion rule

Use this checklist when **adding a provider**, **upgrading its CLI/SDK/protocol**, or **changing an existing provider's behavior**. **This file must be updated whenever a new feature or service is added that changes how a provider behaves.** A provider that can answer a chat is not necessarily integrated with bigbud. Registration, discovery, execution, capabilities, internal generation, durable ownership, UI, and packaging have independent integration points.

This is a reusable engineering checklist, not an ADR choosing a new architecture or a promise that every provider supports every feature. Future “Meta” provider requirements must be specified separately; do not infer a vendor, aggregator, model API, harness, authentication method, or transport from that name. The [existing Muse Code plan](../plans/2026-10-13-meta-muse-code-provider-plan.md) is separate historical/product context, not a default for this document.

**A checked feature means one of two things:**

1. It is integrated end-to-end, with a truthful declaration, server enforcement, UI behavior, and tests/evidence; or
2. It is explicitly unsupported/gated, with a reason, hidden/disabled UI where applicable, a typed runtime refusal before side effects, and a negative test. Document why a gate is inapplicable rather than inventing an endpoint to reject.

Do not use a blanket “all capabilities supported,” an icon in a picker, a green discovery snapshot, or a mocked successful turn as acceptance evidence. Every claimed capability needs its own disposition. Shared provider-neutral behavior should be **verified/reused**, not copied or needlessly edited.

Tags: **ALL** = every integration/update must audit; **NEW** = new serialized provider identity; **UPDATE** = existing CLI/SDK/API/behavior change; **IF** = only when claiming the indicated feature/topology. Sections are ordered by implementation dependency; tests accompany each section, not just the final gate.

## 1. Scope, baseline, and support ledger

- [ ] **ALL** Record task/issue, provider ID/display name, owner, inspected commit plus dirty-worktree caveat, exact CLI/SDK versions, supported platforms/architectures, and links to the native contract and qualification evidence. Preserve concurrent changes; a moving worktree is not a frozen acceptance baseline.
- [ ] **ALL** Clarify whether the work adds a harness, model through an existing harness, direct inference client with its own tool loop, or orchestration/aggregation layer. Clarify local/remote execution, native/shared versus private history, login/API-key lane, initial feature scope, default enablement, rollout, and explicit non-goals.
- [ ] **UPDATE** Diff consumed API/types and behavioral changes: required input fields, optional/nullable responses, event ordering, terminal semantics, IDs, limits, permissions, model catalogs, native data/config migration, and changed dependencies. A package bump alone is not a complete upgrade.
- [ ] **ALL** Complete a support ledger for every row below. Each supported row names implementation, declaration, UI/client gate, server gate, tests, platform/version evidence, and known limitations. Each unsupported row records its reason and negative test. Conditional rows can be inapplicable with an explanation.
- [ ] **ALL** Separate static capabilities from enablement, installation, auth, model availability, setup/permission readiness, and release qualification. Identify the actual authoritative source at each boundary; there is no single global capability file.

## 2. OpenCode v2 lessons to preserve

Start with the current [provider report](../reports/providers-opencode-v2.md), [profile/registration evidence](../validation/opencode-v2-profile-registrations.md), [live-send diagnosis](../validation/opencode-v2-live-send-diagnosis-2026-10-15.md), and [dead-thread recovery evidence](../validation/dead-thread-recovery-2026-10-15.md). Historical plans describe retired designs too; follow production composition before drawing conclusions.

- [ ] **ALL** Keep **provider identity**, **SDK API version**, **canonical event schema version**, and **native runtime version** distinct. Legacy `opencode` imports `@opencode-ai/sdk/v2` in [ServerManager.ts](../../apps/server/src/provider/Layers/Opencode/ServerManager.ts); it is not the `opencodeV2` provider using `@opencode/client`. Editing the legacy adapter or native title helper does not integrate v2.
- [ ] **ALL** Audit hidden generation separately from chat. [RoutingTextGeneration.ts](../../apps/server/src/git/Layers/RoutingTextGeneration.ts) dispatches six operations independently; an available model in [AiSettingsSection.tsx](../../apps/web/src/components/settings/AiSettingsSection.tsx) is not proof of any of them. Current source implements all six for OpenCode v2 through [OpencodeV2TextGeneration.ts](../../apps/server/src/git/Layers/OpencodeV2TextGeneration.ts) and has independent implementation-review approval, including dispatch/settings-race and retained-capacity fixes. See [§16](#16-internal-text-generation-all-six-operations) for remaining validation boundaries; code-review approval does not check off acceptance/native qualification.
- [ ] **ALL** Follow the **final composed** capabilities. [Application.capabilities.ts](../../apps/server/src/provider/Layers/OpencodeV2/Application.capabilities.ts) and the v2 row in [providerRemoteWorkspaceConformance.ts](../../apps/server/src/provider/providerRemoteWorkspaceConformance.ts) describe broader seams, while [Application.composition.ts](../../apps/server/src/provider/Layers/OpencodeV2/Application.composition.ts) explicitly disables production remote paths. The current report documents local shared-native execution only. These are reconciliation targets, not permission to enable retired paths.
- [ ] **IF shared service** Isolate app/profile issuers, registrations, plugin slots, auth, invocation identities, ownership records, and cleanup without forking the user's daemon/accounts. Foreign/legacy slots remain untouched. Shared connection, same logical lineage, same physical storage, and exclusive writer ownership are different facts.
- [ ] **ALL** Validate IDs through the actual native router, not just create-body schema. [Orchestration.sessionIdentity.ts](../../apps/server/src/provider/Layers/OpencodeV2/Orchestration.sessionIdentity.ts) uses lossless full-issuer/full-digest 95-character IDs because the native path segment limit is 100. Existing overlong IDs remain retained evidence, not rekey/migration/replay inputs. Preserve tests for create-success/exact-GET-failure and 99/100/101/142-character boundaries.
- [ ] **UPDATE** Check API compatibility directionally: what requests bigbud sends versus all responses it accepts. See [SharedService.protocol.ts](../../apps/server/src/provider/Layers/OpencodeV2/SharedService.protocol.ts) and [SharedService.protocol.direction.test.ts](../../apps/server/src/provider/Layers/OpencodeV2/SharedService.protocol.direction.test.ts). Nullable response unions, numeric subsets, required query fields, JSON envelopes versus 204, and SSE encoding are not interchangeable.
- [ ] **ALL** Test restart/crash/reboot and exact original-owner cleanup through **production authorization guards**, not only a fake runtime. Dead-backend proof, transport-generation fencing, consent revisions, and stale callbacks can otherwise leave a resumable conversation permanently blocked or permit stale writes. See [Client.guard.ts](../../apps/server/src/provider/Layers/OpencodeV2/Client.guard.ts) and [Orchestration.enrollment.deadBackend.ts](../../apps/server/src/provider/Layers/OpencodeV2/Orchestration.enrollment.deadBackend.ts).
- [ ] **ALL** Treat timeout, lease expiry, lost acknowledgement, and detached transport as uncertainty, not proof work stopped. [Runtime.settlement.ts](../../apps/server/src/provider/Layers/OpencodeV2/Runtime.settlement.ts) and [PluginSetup.activation.jobs.ts](../../apps/server/src/provider/Layers/OpencodeV2/PluginSetup.activation.jobs.ts) retain physical work/receipts after short UI deadlines. Do not solve a hold by deleting ownership or adding a timer that replays work.
- [ ] **ALL** Preserve intentional restrictions instead of calling every missing feature a bug. Current v2 production denies/gates native subagents, remote targets, native rewind/fork/steer/continuation, and some form presentations. Its [adapter declarations](../../apps/server/src/provider/Layers/OpencodeV2/Adapter.capabilities.ts), [subagent evidence](../validation/opencode-v2-subagent-evidence-2026-10-16.md), and runtime refusals must agree. Since `579bae55490`, repository source implements v2 native-family execution (pre-execution permission ceiling, exact child routing, durable family Stop/physical drain, cardless main Stop), yet `providerSubagents.capabilities.ts` still declares `gated`: the isolation, release and exact native-family qualification registries are empty, and stock native lacks the authenticated completion admission supplied by the [native-family prerequisite](2026-10-21-opencode-v2-native-family-prerequisites.md) source extension. Source/review evidence does not promote a gate. Public `learning:false` also coexists with a specifically gated durable review hook; that is not general unattended support.
- [ ] **ALL** Separate discovery from execution/setup. V2 consent, native API/source/plugin checks, exact Location, and evidence registry are provider-specific gates; **do not impose v2's plugin ABI or clean-runner process on every provider**. Conversely, a health/catalog probe is not execution proof for any provider.

- [ ] **IF sensitive native execution/config writes** Define explicit trust and scope separately from enabled status. Pre-consent probes perform only authorized reads; opening a picker/settings/setup view does not grant consent, install a plugin, send a prompt, or select a model. Revoke pending native operations/publication synchronously when accepted settings change.
- [ ] **IF shared connection** Verify registration ownership, bounded reads, literal loopback/origin, no redirects/credential forwarding, generation changes, and platform filesystem protections. Reuse [SharedService.registration.ts](../../apps/server/src/provider/Layers/OpencodeV2/SharedService.registration.ts) as topology-specific evidence, not a mandatory new-provider protocol.
- [ ] **ALL** Test logged-out/expired auth, disabled provider, runtime not installed, unavailable service, transient outage, unauthorized model, account change, refresh from settings, and no billable generation during routine discovery.

## 7. Transport and process ownership

Sources: [RequestDeadline.ts](../../apps/server/src/provider/RequestDeadline.ts), [providerExecutionContext.ts](../../apps/server/src/provider/providerExecutionContext.ts), owned Codex [codexAppServerManager.ts](../../apps/server/src/codex/codexAppServerManager.ts), legacy shared OpenCode [ServerManager.ts](../../apps/server/src/provider/Layers/Opencode/ServerManager.ts), current v2 [ServerManager.ts](../../apps/server/src/provider/Layers/OpencodeV2/ServerManager.ts) and [EventHub.ts](../../apps/server/src/provider/Layers/OpencodeV2/EventHub.ts).

- [ ] **ALL** Document topology: one owned subprocess per session, shared owned manager, borrowed native daemon, SDK transport, or another qualified design. Ownership determines cancellation and shutdown; do not apply Codex's per-session kill behavior to borrowed/shared OpenCode.
- [ ] **ALL** Install response/request/event handlers before session creation or first send. Verify actual SDK framing, envelopes, event stream decoding, buffering, reconnect semantics, bounded errors, and cancellation behavior. Negotiate only consumed features and handle unknown additive fields safely.
- [ ] **ALL** Fit native startup within ProviderService's 45-second budget; bound handshake/read/ack/stop separately. An approval wait or long valid model turn is not necessarily a dead session. A Promise timeout must not leave an uncontrolled side effect able to mutate a replacement owner.
- [ ] **ALL** Serialize session mutation while allowing independent threads to progress. Bound process/session owners, event counts/bytes, retained output, consumers, polling, retries, and queue wait; test burst/saturation and slow consumers. Protect approvals, terminal/state events, and uncertainty evidence from lossy coalescing.
- [ ] **ALL** Use literal executable/arguments and platform-aware resolution, explicit CWD/env, and packaged Node/Electron runtime. Avoid unreviewed shell interpolation, credential-environment leakage, or guessed local fallback paths.
- [ ] **IF shared** Scope event subscriptions, ownership, interrupt, Stop-all, detach, and shutdown to exact bigbud owners. One child OOM/transport error must not cancel every thread or stop the user's daemon. Registration replacement is not proof the original physical process exited.
- [ ] **UPDATE** Qualify CLI/SDK/runtime combinations, actual transport capability changes, and lazy import retries. Version parsing/pin policy is provider-specific; do not substitute a package pin, OpenAPI `info.version`, or filename for verified native version/semantics.

- [ ] **ALL** On disabled/unavailable/foreign/incompatible native history retain read-only canonical content and explain recovery. Never create a replacement, import an entire native inventory, rekey, delete native history, or replay a transcript merely to repair a connection/setup failure.
- [ ] **ALL** Test stop/start, app restart, backend crash, daemon restart/loss, wrong/missing native session, invalid cursor, altered workspace/model/mode, same-profile and foreign-profile ownership, and cleanup after consent is revoked. ## 9. Admissions, retries, and recovery

Sources: [providerTurnAdmission.ts](../../packages/contracts/src/orchestration/providerTurnAdmission.ts), [ProviderTurnAdmissions.ts](../../apps/server/src/persistence/Services/ProviderTurnAdmissions.ts), [ProviderTurnAdmissions.ts implementation](../../apps/server/src/persistence/Layers/ProviderTurnAdmissions.ts), [ProviderService.sendTurn.record.ts](../../apps/server/src/provider/Layers/ProviderService.sendTurn.record.ts), [ProviderCommandReactorSessionOps.recovery.turnStart.ts](../../apps/server/src/orchestration/Layers/ProviderCommandReactorSessionOps.recovery.turnStart.ts), [ProviderCommandReactorSessionOps.recovery.dispatch.ts](../../apps/server/src/orchestration/Layers/ProviderCommandReactorSessionOps.recovery.dispatch.ts).

- [ ] **ALL** Define admission identity and idempotency from native evidence. For durable dispatch use stable canonical request/message IDs, immutable binding and payload fingerprint, reserve/dispatch intent before external work, genuine acceptance, and exact terminal outcome.
