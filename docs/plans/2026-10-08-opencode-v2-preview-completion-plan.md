### Official documentation refresh (8 October)

Sources were fetched directly from official V2 documentation; Context7's `/websites/opencode_ai_v2` corroborated client lifecycle/event semantics. Registry responses were retrieved with `curl` and decoded as JSON. Live docs are not a versioned specification for installed 2.0.19.

1. [Client](https://opencode.ai/v2/docs/build/client): `@opencode/client` is the external HTTP client; native/RPC subscribers share one lazy source per client, with backpressure, no replay and no automatic reconnection. Keep the single bounded manager hub and authoritative repair. `@opencode/client/service` can discover/start/stop a managed service, but bigbud's current private process ownership remains the chosen architecture.
2. [Embedded SDK](https://opencode.ai/v2/docs/build/sdk): `@opencode/sdk` hosts the runtime in-process without a listener. Do not replace the network client with it.
3. [Migration](https://opencode.ai/v2/docs/migrate-v1): three intentional breaking areas are server/client API, plugins and terminal configuration. V1/V2 share binary name and config locations; default installation is not side-by-side. Supported V1 config can be normalized without rewriting; V1 plugins cannot simply be reused. V2 accepts `lsp` config but does not run language servers or provide LSP diagnostics. Dedicated binary and profile setup remains necessary.
4. [Permissions](https://opencode.ai/v2/docs/permissions): last matching rule wins; resource strings differ by action (`grep` uses pattern, `skill` uses ID). Shell has host-user authority, not sandbox guarantees. `always` saves project-scoped grants; `reject` rejects every pending permission in the session. Retain once-only UI replies and verify all affected requests close after rejection.
5. [Plugin guide](https://opencode.ai/v2/docs/build/plugins): tool snapshots are captured per model request; later transforms do not revoke already captured executors. Preserve broker execution-time ownership checks. Current guide documents session permission rules and child inheritance; this differs from the September pinned-source observation. Native child support remains disabled until the selected release is proven, not enabled from documentation alone.
6. [API](https://opencode.ai/v2/docs/api) / [OpenAPI](https://opencode.ai/v2/openapi.json): surface is still described as experimental. Current schema uses `session.remove` and HTTP permission reply body `decision`; the plugin guide shows `reply` and an interrupt `continue` example, while current code uses 2.0.19 `decision`/`resume`. These are different surfaces or documentation drift, not grounds for blind renaming. Resolve exact generated client and runtime signatures first. OpenAPI `info.version` is `0.0.1`, not the CLI compatibility version.
7. [npm client metadata](https://registry.npmjs.org/@opencode%2fclient/latest): latest observed **2.0.26**, schema/protocol dependencies **2.0.26**, Effect peer **4.0.0-rc.112**. bigbud remains **2.0.19**, Effect **4.0.0-beta.43**. Publication is evidence of availability, not conformance. No dependency or CLI was upgraded by this audit.

Older findings about pending-interaction persistence and standard-server session-log replay remain 2.0.19 observations. They were not reprobed against 2.0.26. Do not claim upstream fixed them, or that the original linked issues remain open, without checking the selected release.

## Risks And Decision Gates

- **Live docs versus pinned code:** use exact generated declarations plus runtime conformance. New upstream capability is not proof the installed pair supports it.
- **Trust-model drift:** September denied native tools; current committed source permits explicit native trust. Neither the plan nor a refactor should silently reverse/widen this policy. Native shell permissions do not guarantee private-profile containment.
- **Mutable tool snapshots:** plugin removal/config changes do not necessarily revoke a captured executor. Keep dispatch-time authorization, exact-owner checks and raw-settlement observation.
- **Unknown outcomes:** transport loss is not native exit; timeout is not no-admission proof. No TTL releases uncertain ownership or licenses automatic resend.
- **Profile upgrade/rollback:** separate binaries are insufficient if config/data roots overlap. Native schema downgrade support must be proven on copies.
- **Resource limits:** receipt/event/history limits currently fail closed. Do not remove limits to make scale tests green; design compaction/checkpoints that preserve replay identity.
- **Original scope:** old D8 includes all platforms/targets/workloads. This audit does not silently defer those requirements. Missing environments block their evidence, not independent coding.
