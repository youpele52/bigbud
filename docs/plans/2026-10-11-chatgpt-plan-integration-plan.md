## Summary

Add optional **Continue with ChatGPT** to bigbud's existing Codex provider. bigbud's local server owns browser OAuth, saved registrations, token renewal and revocation. The existing Codex app-server sends eligible requests to the public Responses endpoint with the selected registration's OAuth access token. Existing Codex CLI/native login, API-key/custom provider paths, other providers and speech-to-text remain unchanged.

**Recommended baseline for a future implementation request:** installed Codex binary; local desktop and local Bun/Node server; multiple saved registrations; managed mode off by default; explicit account selection for new work; registration-private native history; official env-token restart/resume; account model catalog and external usage link. Include a local provider runtime working in a remote workspace. Do not add managed downloads, a new provider-instance registry, true remote credential transfer, app billing or a new onboarding wizard.

O1/O2/O15 make the documented flow applicable to open-source/local tools such as bigbud's downloadable MIT distribution. They **do not** authorize every paid offering merely because a feature is free or the repository is open source. Paid or remotely hosted offerings require the documented interest/waitlist path before offering that integration. Individual user/workspace/model eligibility is still checked by OpenAI; neither login nor catalog discovery proves all inference is allowed.

## Problem

Native Codex discovery/login does not implement bigbud-owned dynamic SIWC registrations, consent, account switching or revocation. A new OAuth button alone is insufficient: the child captures its env token at launch; a refreshed token in storage does not hot-update it. Blind replacement can interrupt work, and reading a global active account during retries can misattribute billing/history.

The prior plan also treated ordinary implementation work as a web of approvals. This revision fixes the defaults and confines uncertainty to specific runtime/release checks, while retaining fail-closed behavior for unknown credentials, ambiguous refresh or unsafe history recovery.

## Goals

1. Implement O3's official public-client flow and permission-disabled branch, without client secret/API key/native borrowed client.
2. Preserve separate user/workspace registrations and immutable workload/history ownership across renewal, logout, switching and reconnect.
3. Protect server-only token bundles; serialize rotating refresh across threads/processes and detect crash/uncertain rotation without replay.
4. Use O6's exact public env-token route; restart and strict-resume safely, without hidden background cancellation or accepted-turn/tool replay.
5. Preserve CLI/custom/API-key/other-provider behavior, drafts/attachments, approvals/epochs/bridges, and separate STT credentials.
6. Present accurate account models, route/permission/errors and external usage controls; ship opt-in with additive persistence and safe rollback.

## Non-Goals

- Feature implementation during this planning task; unrelated cleanup, broad checks, dependency/config changes, staging/commit/push.
- SaaS account/billing/credits, new defaults or a generic provider-instance registry; managed binary downloads or true remote provider-runtime transfer.
- Importing ChatGPT chats/context, native CLI auth.json, arbitrary personal CLI config, or decoding opaque workspace/account auth metadata.
- OSS SIWC device-code/API-key exchange. Native Codex supports other login modes; that does not make them substitutes for O3.
- Audio/video/transcription/Files upload; hosted image generation/file search/Code Interpreter/native computer use/MCP/connectors/`tool_search`.
- Zero-interruption renewal of a turn that outlives the captured token, automatic orphan adoption, or a new cross-platform process supervisor.
