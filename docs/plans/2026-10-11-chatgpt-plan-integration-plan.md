## Summary

Add optional **Continue with ChatGPT** to the existing Codex provider. The local bigbud backend owns official public-client OAuth, separate registrations, renewal and revocation. Codex uses a fixed custom Responses provider with **command-backed authentication through a private token broker**, qualified for each enabled build/platform. Ordinary renewal no longer requires process replacement. Existing CLI/native login, API-key/custom-provider paths, other providers and speech-to-text remain unchanged.

Baseline: installed Codex; local desktop and local Bun/Node server; multiple saved registrations; explicit account selection; registration-private native history; account model catalog and external usage link. Managed mode is **off by default**. Local provider runtime operating in a remote workspace is included; remote credential transfer, managed downloads, a provider-instance registry and billing/onboarding redesign are not.

**Documentation reconciliation:** O6 still documents child `ACCESS_TOKEN` followed by restart/resume; that remains a valid SIWC example. General Codex O18 now documents custom-provider `auth.command`, no stdin, bearer stdout, timeout and `refresh_interval_ms=0` for refresh on authentication retry. Prefer that command route only after exact SIWC/build/platform qualification. Do not use native `account/login/start` with `chatgptAuthTokens`, or silently fall back to env/restart on unsupported builds.

O1/O2/O15 describe eligibility for free OSS/local distribution, not every paid offering merely because its repository or feature is free. Paid/remotely hosted offerings use OpenAI's published interest/waitlist path. User/workspace/model eligibility remains external; login/catalog visibility do not prove inference. **Service eligibility is separate from the devkit's noncommercial code license.** Independently implement documented protocol in Effect with maintained `jose`; do not vendor/adopt the devkit.

## Problem

Native Codex login does not implement bigbud-owned dynamic registrations, consent, switching or revocation. Authentication must stay attached to workload/history across refresh, queueing, signout and reconnect. Prior env-token design forced replacement on renewal and proposed a second SQLite coordinator despite today's backend lifetime owner. It also described obsolete Windows inspection-only helpers, unavailable Codex inspection and already-fixed resolver bugs.

Command auth reduces disruption but adds a sensitive helper/broker boundary. It must not expose bearer via argv/environment/descriptors, resurrect cancelled ownership, repeat uncertain rotating refresh or replay accepted inference. General docs support is not live SIWC/platform certification.

## Goals

1. Exact official public-client OAuth with identity/plan-permission separation and no native-client/API-key shortcut.
2. Immutable captured registration/history owner through interactive, queued, delegated and internal workloads; same-slug A/B/CLI remain distinct.
3. Protected server storage, existing backend owner, serialized mutation/singleflight and cancellation-safe atomic rotation; uncertainty without replay.
4. Qualified command-auth broker for ordinary same-process renewal; strict native-history/control/recovery fences for genuine replacement.
5. Preserve CLI/custom/API-key/other providers, drafts/attachments, approvals, queued explicit/inherited semantics, canonical tools, local-runtime remote workspaces and separate STT.
6. Truthful account models/reasoning metadata, route/errors/usage controls and opt-in ownership-compatible rollback.

## Non-Goals

- Feature code/dependencies/configuration, unrelated cleanup, broad checks, staging/commit/push in this authoring task.
- New provider registry, SaaS billing, managed installer, true remote-runtime token transfer or onboarding redesign.
- ChatGPT chat import, native auth.json/personal config import or decoding opaque auth/workspace metadata.
- Device-code/client-secret/native `chatgptAuthTokens` substitution for official SIWC public-client flow.
- Audio/video/transcription/Files upload or unsupported hosted image generation/file search/Code Interpreter/computer use/MCP/connectors/`tool_search`; supported local tools are not blanket-disabled.
- Automatic orphan adoption/reaping, new supervisor, cross-account history transfer, lossless continuation after uncertain/accepted inference, or owner-unaware binary downgrade against managed state.
