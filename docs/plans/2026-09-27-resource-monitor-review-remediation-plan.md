## Workstream A: native transport and package boundary

Owner: existing “Implement Rust monitor transport and desktop bridge” thread. Own `apps/desktop/src/system-monitor/*`, `protocol/system-monitor/*`, `crates/bigbud-desktop-supervisor/src/system_monitor/*`, and staged-supervisor verification scripts/tests. Coordinate before editing shared protocol types.

1. Make `SystemMonitorBridge.retry()` distinguish a healthy native connection with a failed Rust collector from a failed transport. For the former, send the existing typed `RetryCollection` command with a bounded request ID/deadline, await `RetryAck`, and let Rust's `Service::retry_collection()` reset its baseline while retaining subscriptions. For the latter, reconnect a new child and allow the renderer to resubscribe. Do not restart the child solely to retry collection. Prove both paths in bridge tests, including status transitions, subscription continuity, timeout, and a late event from the old child.
2. Complete the plan's handshake identity contract using additive v1 fields and coordinated Rust and TypeScript codecs/fixtures. `HelloAck` must carry hostname, OS name/version, and architecture as available; absent fields are explicit rather than invented. Preserve existing field numbers. Update protocol minor version if required by the repository's version rules. Keep identity in snapshots for baseline/reconnect display.
3. Extend the existing `verify-packaged-desktop-supervisor.ts` path with a bounded `--system-monitor` Hello/HelloAck/Shutdown smoke against the **staged artifact**, while retaining current delivery-supervisor smoke. Use the source schema/codec or a maintained golden fixture, validate major version, frame limit and required capabilities, and reject an older binary without monitor mode. Add a focused test that fails when the staged binary lacks the mode. Avoid OS metric collection during package verification.
