# Implementation plans

**Reviewed:** 22 October, 2026 against the current working tree, including concurrent uncommitted work.

Keep implementation plans, unresolved requirements, operational safety contracts and useful handoff records here. This index separates code that exists from work that is unfinished, deferred or still awaiting runtime/release evidence. Historical “Proposed” headers and old test failures are not reliable descriptions of today's app; use the review notes below and the latest implementation/evidence sections together.

This is a conservative source-and-evidence audit, not a new acceptance review of every requirement or certification of the installed app. A working-tree implementation is not necessarily committed, packaged or qualified on macOS, Windows and Linux. Retained historical plans are not all active backlog items.

## Folder and naming guidelines

- Follow the protected [plan authoring guide](_plan-authoring-guide--do-not-delete.md). Never delete that guide or the protected [test fixture](_test-data--do-not-delete.md).
- Use descriptive, dated filenames with the appropriate extension: `2026-10-22-thread-picker-plan.md`, `2026-10-22-thread-picker.svg`, or another suitable file type. Prefer Markdown for plans; keep supporting assets beside their plan, in a subfolder when needed.
- Keep standalone HTML mockups, interactive demos and visual design experiments in [docs/prototypes/](../prototypes/). These are exploratory examples, not production app pages or implementation plans. Dated naming applies there too, including `.html`, `.md`, `.svg` and other formats.
- Link prototypes to related plans here; keep actual verification evidence in [docs/validation/](../validation/). Do not include credentials or private user data.
- Before retiring a plan, check the implementation and acceptance gaps. Preserve unique safety requirements, decisions and unfinished work in a surviving record; repair inbound links. Completed duplicates and superseded designs should not remain disguised as future work.
- Old authorizations, historical command transcripts and test counts do not authorize fresh provider calls, destructive operations, commits or pushes.

## Main findings

- **Implemented in source:** saved-message search, terminal harness identity, mobile bounded recovery, shared attachment preparation, resource monitoring and the read-only agent resource tool, OpenCode adoption/setup, Claude SDK hardening/subagent display, Games and the SSH config picker. Some retain important native/platform or final acceptance checks.
- **Partially implemented or gated:** terminal exact checkpoints/native ownership, automatic recovery beyond the sleep/wake slice, remote-agent upgrades/conformance, mobile review fixes, connection resilience, native OpenCode qualification/family promotion and delegated model choice on mobile/OpenCode.
- **Still proposed or deferred:** Codex subscription voice/task speech, optional Copilot packaging, project Trunk/Tributaries, Meta Muse, ChatGPT-plan integration, additional harness integrations and the optional Rust-owned background service. Existing neighboring features are not proof these proposals shipped.
- **Retired:** 15 completed or superseded records. Their tracked history remains in Git; useful contracts and unresolved gates survive as listed below. Of 82 original files, 67 remain, plus this README.
