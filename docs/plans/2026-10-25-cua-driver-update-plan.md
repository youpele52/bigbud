## 2. Goal and definition of done

Upgrade the native desktop automation integration from pinned Driver 0.9.1 to the verified 0.38.0 release, adapt its contracts safely, move physical lifetime ownership into a dedicated Rust sidecar, and subsequently replace subprocess execution with independently qualified native Driver SDK execution. TypeScript retains provider/thread orchestration and canonical application settings/domain state; Electron retains installation, permission UX and trusted window ownership.

Acceptance criteria:

1. A platform enables only a coherent, verified runtime/adapter/policy/control tuple. Updating the version constant alone never selects a partially migrated stack.
2. Stage 1 retains Driver subprocess execution and MCP. Lifecycle extraction and the later mediated-MCP safety integration are explicit separate milestones; neither implies an SDK migration or Rust takeover of TypeScript domain logic.
3. All routed desktop actions, including discovery, observations, launch, focus and system-browser navigation, pass native admission. No direct TypeScript MCP route bypasses app restrictions, pause state or control health in the selected supervised mode.
4. Computer use remains off by default. When enabled, applications are granted by default except explicit user disallows and existing hard safety blocks. There is no implicit application allowlist.
5. Foreground is the interaction default; a preference makes background the default. Neither preference selects unrestricted/bypass authorization. Unsupported delivery is refused rather than silently escalated or replayed.
6. One visible amber broad-access notice appears per logical continuous computer-use session, with an app-restrictions link. Consecutive calls and participating turns share that identity; reconnect/daemon restart does not repeat the notice.
7. A dedicated, qualified floating Stop surface and a separate in-chat computer-use Stop are both present. Stop closes desktop admission across all threads until explicit user Resume; agents may continue chatting. No global shortcut is added.
8. Missing/crashed/unresponsive controls, lost control connections and owner/worker failures fail closed. Stop acknowledgement, confirmed physical retirement and uncertain input effects are distinguishable. No confirmation dialog delays emergency Stop.
9. Observations and exact targets survive legitimate multi-call work but cannot cross caller, policy, pause epoch, runtime, process lifetime, window or geometry boundaries. Old coordinates never execute against a silent recapture or a newly frontmost window.
10. Settings, schemas, every public tool consumer, activities, packaging and rollback are migrated together. Existing browser automation remains separate. Relevant focused checks and separately authorized packaged qualification pass; unsuccessful checks are reported honestly.

Do not transplant Hermes tool/approval defaults, assume old flat schemas equal the new typed SDK, or infer that its integration qualifies bigbud's exclusions, floating controls, TCC ancestry or platforms. ### M1 — Stage 1A: physical lifecycle extraction, still subprocess/MCP

Use one `crates/bigbud-computer-use` executable with explicit roles: **guard** owns the exclusive lock, durable safety record and emergency retirement; **owner** owns authenticated mediation, reference tables and trusted projection; **worker** owns stock Driver `serve`/MCP in Stage 1 and native SDK execution in Stage 2; a bounded **launch broker** runs outside execution containment. Electron starts guard; guard starts owner and worker. Rust owns one physical-desktop lane. TypeScript constructs ordered logical tool plans and owns orchestration/domain presentation; Rust validates frames and projects responses before any TypeScript egress. Stage 1 retains MCP, not embedded SDK calls.

- Use a per-user root independent of `baseDir`, profile and release channel: macOS `~/Library/Application Support/bigbud/computer-use`; Windows `%LOCALAPPDATA%/bigbud/computer-use`; Linux `$XDG_STATE_HOME/bigbud/computer-use` or `~/.local/state/bigbud/computer-use`. An OS-exclusive lock elects the controlling interactive desktop; competing desktops/profiles report an explicit conflict. Pause persists across login/profile changes. Refuse overlap with unsettled managed roots; never adopt arbitrary Driver instances or kill by process name.
- Bootstrap authenticated local pipes/Unix sockets with restrictive permissions/ACLs and one-use instance capabilities, verified peer/process lifetime where supported. Do not use an unauthenticated loopback listener or expose credentials/endpoints to providers/renderers.
- On macOS/Linux, use a worker process group with a qualified known non-detaching helper closure, recorded creation identities and an independent lifeline watcher; use Linux pidfds where available. Keep the group anchor unreaped until settlement to prevent group-ID reuse. No mandatory `sandbox-exec`, no-fork assumption or delegated cgroup requirement. The tool allow set bounds the known closure; qualify any actual detaching helper separately. Known macOS helpers include `screencapture -l -x -o`, `ps` and selected `lsof`/`codesign`/`otool`/`osascript` inspector routes: pin trusted utility paths, sanitized environments and bounds, never expose arbitrary scripts.
- On Windows, create execution roots suspended, assign a no-breakaway Job with kill-on-last-handle-close, record exact roots, then resume. Only guard/owner hold noninheritable Job handles. Broker stays outside this Job/group and owns only tracked launch processes; ordinary launched user apps survive Stop. Submission-before-cancellation can have an unknown launch outcome; never replay it.
- Record exact execution roots durably before admission. Recovery compares creation identity, not PID alone: a reused PID means the old process ended, never permission to kill the replacement. No replacement until the known helper closure settles; unclean recovery starts paused.
- Guard death triggers independent owner/worker lifeline watchers; owner/control loss makes guard retire execution; worker death makes guard retire remaining execution helpers. Watchers stay serviceable during blocked native/MCP work. This covers individual supervised-process failures, not simultaneous destruction of every supervisor or an unscheduled OS. It cannot undo OS-delivered input. Missing retirement evidence keeps admission closed.
- Install/update/repair quiesces callers and old roots before replacement. Existing Electron restart timers and server reset paths must not compete with native ownership once the supervised tuple is selected. A worker restart never authorizes replay or clears pause.
- Isolate all Driver config/history/cache state using explicit managed `CUA_DRIVER_RS_HOME` and compatible aliases where source requires them, passed as overrides through every sanitized launch. Do not inherit standalone history/config or assume the currently created but unused home directory already isolates state. Keep telemetry/update checks disabled.

**Exit:** dummy-worker/real-process lifecycle tests, duplicate-owner/owner-death/retirement tests and packaging identity checks. Stage 1A may land dormant, but **cannot independently enable the new runtime or safety UI**. Existing legacy behavior remains selected until M2–M6 form a qualified tuple.

### M2 — Stage 1B: explicit mediated MCP admission/enforcement

Add native mediation as a separately identified integration step, not an implicit consequence of supervision. TypeScript builds an ordered logical call plan; native envelopes carry bounded MCP frames plus owner-issued operation/session authority. Rust validates and stamps exact session/PID/window/capture fields losslessly and parses raw replies into a trusted filtered projection **before** TypeScript receives results. TypeScript decodes that projection for domain presentation, not raw unfiltered Driver replies. In selected supervised mode there is no direct `spawn(cua-driver)`, raw daemon socket/Driver route, `open.default`/unchecked `Open.openBrowser`, reset fallback or arbitrary native invocation.

The native boundary validates method/tool/arguments, exact admitted operation and target, current policy, pause epoch and control lease **for every forwarded desktop primitive**, including helper reads in a compound public action. Allow only required helper/tool sequences for the admitted action. Initialization and inventory are metadata-only; agent calls cannot gain arbitrary `run_steps`, script, history, perception, browser, file output or operator/permission APIs. Reserved transport fields are owner-stamped, never model authority.

#### IPC and state semantics

| Message/state                          | Required semantics                                                                                                                                                                                                                                                                                    |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Hello` / negotiated capabilities      | Protocol major/minor, build/tuple identity, role, owner/worker generations, limits and qualification profile. Reject incompatible peers before operations. No adoption based on claimed PID alone.                                                                                                    |
| `ApplyPolicy`                          | Authenticated server projection with schema version, monotonic revision/digest, enablement, disallowed app identities, delivery default and limits. Desired and applied revisions are distinct. Duplicate same revision/digest is idempotent; conflicting digest/stale revision is refused.           |
| `BeginEpisode` / participation         | Server supplies trusted caller/thread/turn or explicit bounded invocation-lifecycle identity. Owner returns logical session identity; no provider-supplied participants or inference from daemon idle time.                                                                                           |
| `AdmitOperation` / mediated MCP frames | Operation ID, canonical request digest, caller, episode/native session, expected pause/policy/worker generations and target/observation references. Owner returns a single-operation ticket; every helper frame is checked against it. A cancelled/expired queued ticket cannot execute later.        |
| `Stop`                                 | Separate priority channel, operation ID and expected desktop scope. Close admission/advance pause epoch before waiting on data work. Return revocation acknowledgement and a physical-settlement handle separately. Idempotent retries observe the same stop operation.                               |
| `Resume` / check-in continuation       | Separate human-control capability, fresh challenge and current pause epoch. Accept only after retirement/input-state/policy/control prerequisites; a delayed Resume cannot clear a newer Stop. Ordinary chat/model calls/settings refresh cannot mint it.                                             |
| `SurfaceLease` / `WarningPresented`    | Bound to actual registered renderer/native host identity, owner generation, display qualification and episode notice ID. Renderer responsiveness is proven by challenge/response, not a main-process timer inventing health. Only current notice presentation may acknowledge it.                     |
| `Status` / operation result            | Bounded snapshot/versioned events: enabled/disabled, ready, paused(reason), stopping, retirement-unknown, unavailable; applied policy, epochs, control health and queue status. Terminal result distinguishes not-started, completed and unknown effects. Gaps require snapshot, not mutation replay. |

Use bounded length-prefixed frames; validate before allocation, reject malformed/truncated/oversized data, preserve field numbers/enums, and maintain request-ID/digest deduplication. Accepted mutations are never resent after disconnect. Retained operation status may expire to an explicit `unknown/expired`, never to permission to execute again. Separate replay rejection from the bounded result cache: use owner-issued, generation-bound tickets and monotonic per-caller acceptance sequences/high-water marks. Evicting an outcome must not make its operation acceptable again; older sequences refuse even after result eviction, and owner restart rejects all old tickets. A lost response is recovered through authenticated, caller-scoped status lookup, never by resubmitting the action under a new operation ID. Lookup rechecks current egress policy and returns content-free settlement metadata when the original payload is no longer authorized. Conflicting digests always refuse; cancellation must work before admission acknowledgement reaches the caller. No provider credentials or sensitive content in control records.

**Final-dispatch boundary:** validate policy and exact target before admission and immediately before forwarding; use the selected Driver route's own target/focus validation and refuse observed identity/focus changes. Neither these checks nor an upstream callback provide atomic isolation against concurrent human or external-process desktop changes. For each shipped route, document reachable target validation, fallback, activation/restoration and post-return behavior. A limited upstream authorization callback does not invalidate first-party mediation or require a new callback on every input event. Refuse specific routes with demonstrated policy/privacy gaps; do not infer that all input is unsupported. A needed upstream change requires a separately reviewed revision/patch decision, never an automatic fork, bypass or alternate-backend replay.

Check target/process lifetime, policy, references, control lease and clocks both predispatch and immediately before every helper. Maintain one Driver session per caller across capture→action, independent of warning episodes, with one global physical lane. Stage 2 retains these checks through typed methods or constrained native `call_tool` for live delivery fields.

#### Caller authority and bounded scheduling

Bind admission to trusted server context: thread/caller identity, provider generation and current runtime-mode revision. Retain TypeScript ownership of that domain state; send a narrow revisioned permission projection to native admission. A queued mutation cannot execute after its thread leaves full-access mode, its caller is cancelled, or its provider generation is replaced. Propagate revocation independently of the data queue, invalidate old tickets, and retire affected in-flight work when needed; no model-supplied runtime-mode flag is authoritative. Test downgrade/cancellation between enqueue, admission and each helper.

Use FIFO within each caller and round-robin selection across callers; a compound physical sequence is non-interleavable until its outcome/required retirement is settled. A public `wait` uses a cancellable owner timer outside the physical lane, so a 15-minute wait cannot monopolize the desktop. At completion, any requested capture re-enters admission against the retained exact target, current authority and original deadline; intervening mutations invalidate old observations. Do not split a compound input sequence merely to improve fairness.

### M3 — Policy, observation and public-contract migration

#### Application restrictions and revision transactions

- Store platform-qualified application selectors: macOS verified bundle/code/path identity; Windows package/AUMID or canonical executable identity; Linux desktop-entry/resolved executable identity as available. Live grants additionally bind PID/start identity and native window ownership. Labels are presentation, not authorization. Group helpers only with verified owning-app evidence; ambiguity refuses that target, not a hidden application allowlist.
- Persist a complete atomic protected `computerUsePolicy` in existing settings: format marker, `authorityId`, namespaced decimal-string revision, digest, enabled, `disallowedApps` (including `[]`), delivery default, existing limits and diagnostics boolean. Never recursively strip this group or marker even when all values equal defaults; explicitly fix `stripDefaultServerSettings` in `apps/server/src/ws/serverSettings.persistence.ts`. Generic settings writes preserve the group; dedicated authenticated human policy RPCs mutate it.
- Native grants a writer lease to one controlling server per authority. Its small durable safety record contains controller installation/profile generation, highest acknowledged revision/digest, migration binding, pause epoch/latch, armed marker, exact execution roots/retirement and episode notice identity. TypeScript settings remain canonical policy values; native keeps only an in-memory projection, not a second policy journal. Human takeover fences/retires the old controller, selects a new revision namespace and requires Resume; never silently merge profiles.
- Transaction order: fence/revoke first → settle old execution → durably persist desired next revision → native validates/applies projection and durably acknowledges revision/digest → reopen only under the same fence with no newer Stop/control/check-in failure and required warning satisfied → UI reports desired/applied separately. Snapshot invalidation precedes asynchronous notification. Failed persistence/ack stays pending/paused. Desired-ahead-of-ack crashes reconcile the exact desired revision; identical revision/digest is idempotent, conflicting digest refuses.
- Serialize dedicated policy Apply and generic settings writes through the same settings writer. Apply carries expected authority/revision/digest and rejects a stale editor instead of overwriting a newer restriction. Construct changes from the latest persisted document inside the writer; unrelated settings writes preserve the exact protected policy group and cannot restore legacy enablement/limit fields over it. Freeze canonical digest encoding (UTF-8, fixed field ordering, decimal revisions, deterministic selector ordering) in cross-language golden fixtures.
- Treat file-watch events as invalidations, not automatic policy changes: atomic renames from an ordinary settings save with unchanged canonical policy must not pause computer use. Admission rereads/validates the protected policy group; missing, unreadable or changed policy fences. With native unavailable, ordinary settings remain usable while preserving the policy; a human restriction/disable may persist as desired and pending but cannot claim enforcement. Grant expansion/Resume cannot become effective without native acknowledgement. Test concurrent Apply, generic saves, self-generated watch events and native-offline recovery.
- Marker-absent migration is permitted only for a recognized raw legacy format with no known migration in native binding. Preserve old enablement/limits as intent with empty disallows and require first human Resume; new installations are disabled. Missing/corrupt/unsupported modern data fails closed rather than field-wise grant-all recovery. External file edits fence via watch plus admission-time reread; preserve the file and require human Apply under a fresh revision.
- Durability uses same-directory temporary file, flush, atomic replacement and qualified directory/full-flush semantics per OS. Revoke before disk I/O; persist armed before any admission. Clear armed only after clean retirement with no latch. Restart while armed is paused. These rules do not claim protection against malicious same-user storage rollback.
- Policy changes invalidate affected observations/caches and fence stale queued work/results. If a worker may still execute old authority, retire it before acknowledging enforcement. Egress checks the current applied revision immediately before forwarding/persisting. No claim of instantaneous undo for previously admitted effects.
- Resolve launch/focus identities before dispatch, including cold launch and already-running cases. Resolve HTTP(S) system-browser handler to an exact checked application and use a qualified handler-bound native opening route; never retain `open.default` as an enforcement escape. Do not automatically use macOS `launch_app(urls)` because of its demotion watchdog.
- Internal inventory may inspect excluded identities solely for enforcement/human settings. Agent discovery filters structured arrays, legacy aliases, counts, text, summaries, warnings, next-call hints and errors. Reconstruct trusted output; string truncation or removing one JSON array is insufficient. Never skip an actually disallowed foreground target and silently act on an allowed window behind it.
- Window captures must have qualified target-pixel provenance. Reject unqualified desktop crops/fallbacks, including Windows paths losing occlusion provenance. Accessibility-only routes may qualify separately. Do not add whole-desktop screenshots, Spaces navigation or perception/history tools to work around a restriction.
- Persist only admitted/projected screenshots. Bind reusable screenshot/attachment references to their provenance so fresh computer-use responses cannot reintroduce invalidated captures. Preserve user history/ownership; do not promise retroactive revocation of immutable cached URLs or already transmitted model context. A separate deletion/retention feature is out of scope.

### M4 — Logical session, required controls and durable pause

Episode state is `preparing` → `warning/control-ready` → `active` → `draining` → `settled`, with a paused state carrying reason/epoch. Metadata-only preparation has a 10 s budget before desktop admission; the first actual primitive starts check-in. The episode spans calls/tool gaps/participating turns until all participants settle and queued/in-flight/delayed work drains, or Stop/disable closes it. An individual Driver call/idle expiry is not an episode. Reconnect and generation retirement preserve notice identity while invalidating execution references; armed process restart stays paused. Explicit Stop closes the episode; explicit Resume permits a new one.

Implement a server episode coordinator from trusted dispatch context (provider generation, caller/thread/turn) and `apps/server/src/orchestration/Layers/ProviderRuntimeIngestion.ts` lifecycle events **before** throttling: turn started/completed/aborted and provider/control loss, not activity counters. Reconcile provider gaps and participants every 2 s, with a 10 s maximum participation lease and at most 256 participants; uncertainty pauses rather than fabricating renewals. Ad-hoc calls have actual invocation finalizers and bounded participation no longer than the accepted action timeout (maximum 60 min). Renew only from verified live lifecycle state. Driver sessions remain independent of this coordinator.

Broad access means a valid applied policy with zero user-disallowed apps; built-in hard blocks still exist. Show the amber warning once before first broad-access use in an episode. If the last exclusion is removed mid-episode and no warning was yet shown, show it before subsequent broad-access work. No repeated toast on every call or daemon restart; no use of enrollment `hasSeenComputerUsePrompt` as this cadence state.

Persist one notice ID with `required`/`presented_unconfirmed`/`acked` state. If acknowledgement is uncertain after a crash, reconcile the same visible card/ID rather than minting a new warning. This guarantees logical notice identity, not exactly-once human perception. Check-in continuation keeps the episode; Stop/new Resume creates a new episode.

Create an always-present-during-episode safety window independent of `floatingAssistantEnabled`, mascot visibility and compact-chat hiding. It hosts Stop/status and the visible amber notice with a fixed “Manage app restrictions” action. Keep a desktop-visible owner/acknowledged notice identity across window changes; main-window-hidden toast or historical activity replay is insufficient. A recovered renderer reconciles current status/notice rather than replaying all historical warnings.

- Add a narrow `computer-use-stop` registry role and a dedicated restricted safety preload/renderer entry point. Do not load the broad `preload.ts`, normal app bootstrap or backend-connected route. **Audit every reachable IPC registration, including handlers without sender checks**, not merely existing `isTrusted` calls. In particular, inspect backend credential discovery in `window/ipcHandlers.ts` and permission/install/doctor handlers in `window/ipcHandlers.computerUse.ts`. Every handler must validate its explicit allowed role, live registered WebContents, main frame and current document generation before returning data or causing effects. Unknown roles, subframes and stale frames deny; synchronous denial must return a bounded result rather than hang.
- The safety preload exposes only bounded status/challenge events, Stop, warning acknowledgement and fixed app-restrictions navigation. No generic invoke/send, backend credentials, permission prompts, installer/repair/doctor, general settings writes or Resume. Use an isolated ephemeral renderer session and fixed bundled resources; deny network (including localhost), external navigation, new windows, downloads and permission requests. Preload API absence is defense in depth; handler authorization must independently reject direct forged messages. Add negative tests exercising every registered production channel against the safety role, unknown senders, subframes and stale documents, asserting both no returned secrets and no side effects.

No arbitrary navigation/shell IPC, settings writes, app quit/restart, permissions prompts or Resume. Resume is a distinct human action in trusted main chat/settings UI, with a current owner-issued challenge; never exposed as an agent tool.

Register hide/close/crash/unresponsive/control-loss/display-change paths. Missing/unqualified surface means no new desktop observations or actions; disappearance revokes admission and starts retirement. Restoring the window does not silently resume.

#### Native clocks and limit changes

Guard owns suspend-inclusive monotonic deadlines: macOS continuous time, Linux `CLOCK_BOOTTIME`, and qualified Windows uptime. First actual primitive anchors check-in; turns, tool gaps, reconnects and chat messages never reset it. Only human Continue resets it, or a fully settled new episode obtains a fresh anchor. Shrinking check-in uses the minimum of the old deadline and original anchor plus new limit; growing applies only after next human continuation/new episode.

Check expiry immediately before each helper and in an independent loop at most every 100 ms. Expiry revokes queued work, retires in-flight execution and suppresses stale egress while retaining known/unknown outcomes. Suspend closes admission; wake checks deadlines before any data work. Never persist a monotonic timestamp across process restarts; armed restart is paused. A fresh one-use human challenge cannot clear a newer Stop/epoch.

An operation deadline begins at acceptance and covers preparation, queueing, every helper/chunk and post-action capture. Reconnect/chunking never extends it. Limit shrink tightens outstanding deadlines; increases affect new operations only. Cancelled/expired queued operations never execute later. Preserve the 10 min check-in (1–60 min) and 15 min action timeout (10 s–60 min) defaults/ranges; browser deadlines and behavior remain independent.

## 9. Risks, rollout and rollback
