## G1 — What selects the initiating machine's Git transport

**Entry-point boundary.** “Local” Git means the repository is local to the backend process, not that the backend is an Electron/laptop process or that the repository's remote uses HTTP. The [shared RPCs](/Users/youpele/DevWorld/bigbud/apps/server/src/ws/wsRpcHandlers.gitTerminal.ts#L169-L296) reach Git on a deployed authenticated client backend (R) as well as D/V/N. The [Git manager](/Users/youpele/DevWorld/bigbud/apps/server/src/git/Layers/GitManager.ts#L210-L316) rejects a nonlocal execution target for PR lookup/preparation and rejects nonlocal `create_pr`/`commit_push_pr`. Remote commit/push use the target Git path instead. These checks do not reject a local repository with a configured SSH remote. `ssh → remote git` and remote-agent Git remain separate from the G1 initiating transport.

**Do not infer `gh`'s checkout algorithm from bigbud's argv.** The [wrapper](/Users/youpele/DevWorld/bigbud/apps/server/src/git/Layers/GitHubCli.ts#L164-L173) resolves `gh` through the process environment, passes cwd and a 30 s deadline to the generic runner, does not pin the CLI version or pass an interruption signal to that runner, and inherits its default output bounds (8 MiB per stream). The local help confirms `--force` resets the branch; neither it nor this wrapper establishes when the installed CLI chooses a configured remote, a PR ref, a head/fork URL, or its own protocol configuration. Actual child commands, paths and credential/checkout behavior are version/config-dependent evidence to capture, not reasons to preselect HTTPS or reuse the direct-worktree clone-URL rule. Keep direct Git's 30 s/1,000,000-byte defaults and the 5 s background fetch distinct from the `gh` wrapper; none is a pack pipe size or proof of descendant reap.

### G1 handoff and required traces

Use the [existing rewrite recorder](/Users/youpele/DevWorld/bigbud/apps/server/src/git/Layers/GitCore.service.status.sshRecorder.test.ts) as the direct-Git baseline, not as evidence of `gh` or a native fence. Capture process ancestry and endpoint attempts even on failure. No live GitHub needed: use synthetic API responses on an isolated fixture for the installed `gh`, disposable bare repos and an owned loopback transport. A fake `gh` is useful to exercise the product branches, not to qualify real `gh` selection.

1. **Direct positive/control:** refresh a tracking branch and invoke explicit fetch, pull and the stacked push via real product entry points. Compare no-transport local status, upload-pack from the rewritten fetch destination, and receive-pack for **each** effective push URL. Show which extra read calls came from status pre/post work. Include linked worktree/common-dir with worktree-specific config, ordinary HTTPS/local-path control, and an explicit SSH URL plus SCP-like form/alias/custom port. Compare separate read/write refs and both network destinations without logging credentials.
2. **Delegation positive/control:** capture `gh → git → [transport]` for local checkout of same-repo and fork PRs, matched versus absent configured remotes, SSH/HTTPS preference versus `insteadOf`, and an existing-branch `--force` case. Deliberately fail the upstream-config step **after** a successful fork fetch to distinguish two independently selected reads from a retry. Include lookup-only metadata and `create_pr` with explicit head; isolate the direct push phase in `commit_push_pr`, then assert no `gh`-initiated receive-pack in either create path. 3. **Admission negatives:** bind `gitRemoteTransport` to the exact action/phase, canonical repo/worktree, effective destination, path, generation and fixed read/write service. For a denied sibling push destination capture all refs: no unauthorized write, no silent dropped destination or success report; distinguish a permitted destination that already accepted a write from one never attempted. Keep preflight vs late transport failure visible rather than promising cross-server atomicity. Check that a soft status/PR error cannot hide an unauthorized spawn.
4. **Configured helper and lifecycle probes:** record `GIT_SSH_COMMAND`, `core.sshCommand`, `GIT_SSH`, command/config injection and `ssh.variant` selection in isolated fixtures, including a wrapper that relocates the executable; compare direct and `gh` trees. These are candidates for extra initiating edges under ambient Git config, not asserted defaults or grants for arbitrary scripts. Fail closed if they attempt unmanaged SSH. Cancel or lose the owner after pack starts; trace process/lease reap and another concurrent lease remaining live. If a push/ref update or PR receipt was lost, inspect authoritative state; do not replay. Capture both the public Git/`gh` error or softened result and the distinct owner outcome.

No implicit exemption for an indirect subprocess, no new generic argv/env grant, and no request here to weaken the plan's intentional OpenSSH config denials.

## C12 — Deployment approval versus workspace-mode claims

- **D/V/N deployment only.** The actual [RPC](/Users/youpele/DevWorld/bigbud/apps/server/src/ws/wsRpcHandlers.remoteBackendDeployment.ts#L12-L37) returns `RemoteBackendDeploymentError(unavailable)` when mode is remote, the auth token is absent, or the service is absent. It is not enough to observe an unauthenticated socket rejection. In an admitted local process, [approval](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/deployment.approval.ts#L14-L36) requires an **exact** remote-agent target ID (not alias substitution). It may use a saved agent selection or a [read-only registry probe](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-agent/remoteAgentLocalControl.approval.ts#L17-L38) looking for a present managed build. `approval-required` is a no-mutation condition, not necessarily zero SSH; invalid target/role must not trigger that probe. Host-trust failure in approval or in preflight is `unavailable`; `host-changed` is a later mismatch between the successful host probe and the stored deployment profile, not the same as OpenSSH rejecting a changed key.
- **Deploy lifetime and recovery.** The [service](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/deployment.ts#L62-L111) checks durable request receipts before approval; completed replay with the same target and boot selection returns the profile without another launch. [In flight](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/deployment.ts#L174-L224), identical request ID joins, changed selection is `conflict`, different ID on that exact target is `busy`, and cancelling the RPC wait does **not** cancel the deployment service's operation. Service shutdown signals its owned runner. A host probe finding the completed authority for this request [skips setup and its input uploads](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/deployment.ts#L111-L146), but still stages/validates the graph, runs start and reads completion; it is not the local durable-receipt path. For an interrupted step, check what _actually_ reached the host: the [completion stage](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/deployment.remoteSetup.ts#L198-L231) distinguishes unreadable completion (`setup-failed`) and receipt for a different request (`conflict`); neither proves rollback. Preserve boot selection and stable request ID. Enforce artifact byte policy independently of stdout: [staging](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/deployment.fetch.ts#L105-L172) treats pinned URL fetch and archive stdin as different steps, and metadata/setup input is not a generic stdin grant. Use the existing stage ceilings from the operation inventory; a caller disconnect and a transport timeout are different observables.
- **R workspace-mode claims are reachable.** The [orchestration gate](/Users/youpele/DevWorld/bigbud/apps/server/src/orchestration/Layers/OrchestrationEngine.commandProcessing.ts#L119-L137) runs after the command has produced an event proposal and before workspace event preparation. [Gate rules](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/workspaceMode.gate.ts#L48-L78) use reserve for project creation/reconfiguration/folder change and lazy claim for qualifying thread turn/message submission. In R a local target uses local `remote-runtime` storage; a parseable SSH target uses SSH for `laptop-runtime`, irrespective of backend mode. The [gate](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/workspaceMode.gate.ts#L107-L173) allows `unsupported` and caches by exact target/root (5 min); explicit reserve throws `OrchestrationCommandInvariantError` on store failure, while lazy store failure warns and caches a skip. An actual conflicting holder refuses **both**. [Reservation](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/workspaceMode.reserve.ts#L9-L52) has eight contention attempts separate from the per-inspect retry ceiling. Lost publish reply reconciles only an exact matching record; no automatic republish on an inconclusive read. Bind publish to the inspected account/host/root fingerprint and generation, not a requester-chosen record path. [Conversion](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/workspaceMode.conversion.ts) has test call sites but no shipped route/import found in this checkout; don't grant it merely because it shares the store.

**C12 traces:** On each covered D/V/N launcher use the real authenticated RPC: saved-selection and registry-probe approval, valid install with both artifact sources in controlled fixtures, exact bytes/EOF, boot and receipt identity, joined waiter and a canceled waiter that rejoins without an extra launch. Prove a lost publish reply reconciles exactly once, and an inconclusive read does not republish. Count reservation transport separately from any downstream provider launch after a lazy skip.

## C13 — Viewer lease, channel and receiver are three different boundaries

- **Lease admission is not SSH establishment.** [RPCs](/Users/youpele/DevWorld/bigbud/apps/server/src/ws/wsRpcHandlers.remoteBackendRelay.ts#L17-L64) require locally authenticated mode and a live caller; deployed mode yields `RemoteBackendRelayError(unavailable)`. List and open resolve persisted [public vs private profile projections](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/deployment.profiles.store.ts#L9-L75); an empty directory lists `setup-required`, an absent ID in the persisted directory opens as `not-found`. The renderer has no authority to supply the target, Node/helper hashes or backend credential. [Lease table](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/clientRelay.leases.ts#L39-L205): 32 total, four per caller; same caller/profile/request ID joins, a changed profile is `conflict`, cancelled/closed request is `caller-closed`, quota is `limit`, foreign lease close returns `closed: false`. RPC close by request ID can cancel before acquisition. [Replay history](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/clientRelay.nonces.ts#L11-L56) is capped at 128 per caller and 4,096 total by default; canceled nonces are retained until caller retirement, not reused when the channel drains. Caller loss disposes its entries, not other callers' channels. A returned lease is a loopback listener and a local credential; [creating it](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/clientRelay.owner.ts#L19-L33) does not connect SSH. A later admitted HTTP request/upgrade that needs a new upstream socket triggers readiness, trust and child launch.
- **Channel caps and errors belong to their respective layers.** [Loopback owner](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/clientRelay.owner.ts#L19-L110): eight upstream sockets, up to two free, 32 inbound connections; wrong HTTP Host/origin is 403, wrong local credential is 401 and incompatible revision 426. Rejected upgrades destroy the socket before upstream (not a guaranteed HTTP response code). [HTTP proxy](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/clientRelay.http.ts#L21-L98): 16 KiB headers, 16 pending requests, 32 MiB counted ordinary request body (overflow destroys request/upstream), 60 s upstream HTTP inactivity and 15 s upgrade timer. Those are not WebSocket frame or SSH stream caps. The [channel bridge](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/clientRelay.owner.channel.ts#L4-L30) uses two 64 KiB high-water marks, not hard end-to-end byte credits. A hash mismatch for the remote executable/helper happens **inside** the launched SSH command, before helper execution; that differs from local invalid profile and failed trust before relay spawn. HTTP upstream channel failure can appear as 502 after open succeeded, not as an RPC open failure.
- **R receiver is not a launcher.** [Receiver](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/clientRelay.entry.ts#L8-L24) reads the named account authority's private credentials and opens the [client Unix socket bridge](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/clientRelay.remote.ts), which adds its own bearer upstream. It does not forward the caller's local relay credential as that bearer, and neither credential grants access to the separate peer socket. Receiver failure exits 1 with a generic diagnostic.

**C13 traces:** Use D/V/N authenticated relay RPC plus real disposable R receiver. Trace list/open with zero SSH, first valid HTTP and WebSocket upstream open(s), reuse versus another channel, binary final stdout after stdin EOF, slow-reader pressure, caller disconnect/close, and confirmed reap with an unrelated lease still working. For HTTP record wrong origin/Host, token and revision, and for upgrades record actual rejection/destroy plus zero attempts. Exercise pending/connection/body limits and cancel-before-open using separate caller IDs. Test a missing persisted profile and a wrong authority before relay launch, key failure after the trust probe but before data SSH, and tampered Node/helper after data SSH but before receiver. Include full receiver stdin→private socket→authenticated response, missing socket/credential and wrong authority; receiver PID has no outbound SSH children. Attempt all three outbound relay RPCs on the authenticated R client route: `unavailable`, zero listener/SSH admission. Do not infer an R-wide SSH prohibition from this result.

## C14/G3 — Coordinator enrollment, pinned transport and worker grants

- **Actual role check.** On [R's authenticated client router](/Users/youpele/DevWorld/bigbud/apps/server/src/server.remote.routes.ts#L20-L37), `server.peerPairing` uses [retention-mutation middleware](/Users/youpele/DevWorld/bigbud/packages/contracts/src/server/rpc.remotePeer.ts#L8-L12). - **Enrollment is not trust approval.** [Pairing branches](/Users/youpele/DevWorld/bigbud/apps/server/src/peer-orchestration/peerPairing.ts#L121-L205) separate status, key ensure, host scan, save, record-grant and revoke. Save accepts a validated, explicitly confirmed pin; the legacy handler does **not** require a prior scan receipt. Don't make an unverified scan authenticate a pin or silently require scan to preserve existing manual pin entry. `record-grant` records the worker's grant ID and kicks followers; it is not worker-side approval. The worker grant still binds coordinator authority and the exact key fingerprint. The owner-side enrollment grant for `inspectPeerHostKey` must be exact host/port and one-shot. [Key generation](/Users/youpele/DevWorld/bigbud/apps/server/src/peer-orchestration/peerSshKey.ts#L67-L93) has a 15 s helper timeout and refuses a nonprivate or wrong-account directory/existing private key. `ensurePeerCoordinatorKey` must never expose private key material.

[Legacy SSH args](/Users/youpele/DevWorld/bigbud/apps/server/src/remote-backend/peerRelay.ssh.ts#L75-L158) explicitly select dedicated identity, pinned host alias, batch and no user agent/password/forwarding. `-F` is optional and the shipped transport does not pass it. Thus the existing args/test override are **not** proof that ambient config (proxy or a multiplexed master) is excluded. The plan requires an isolated pinned-peer descriptor; prove zero ambient helper execution and zero attachment to a pre-existing ordinary master. Preserve `host-identity-mismatch` versus `authentication-refused` (setup errors), unreachable/partial reply (transport failure), and a valid refusal from worker HTTP after successful SSH, not one generic failure.
