# SSH alias compatibility in bigbud

People who already connect with an SSH alias should be able to select it in bigbud. The connection should use the same supported destination, login, port, and identity. Zed demonstrates this experience by using the initiating machine’s OpenSSH client and presenting its prompts in the app. [Zed remote development](https://zed.dev/docs/remote-development)

1. **Use the existing alias picker.** Bind the selected macOS development alias to a generated, private config and resolve it through the Rust owner in normal development composition. Keep the fixture bound to its generated identity, known-hosts file, and exact loopback endpoint. Verify the alias through the same picker used by the server, including first-use trust and a real folder read.
2. **Make connection refusals actionable.** Preserve typed distinctions on the folder RPC for unsupported configuration, changed host keys, unaccepted authentication, transport failure, and owner availability. Preserve the current trust prompt and legacy response compatibility. Redact config values and file paths from native startup diagnostics.
3. **Qualify supported routes against OpenSSH.** Use disposable configs for comparison, then exercise real key-only jump routes and the restricted connector specified by the ownership plan. Require independent host verification for each hop. A changed hop key must stop the route before authentication to the destination. Validate the supported system defaults on their actual platforms.
4. **Reuse connections within the owner boundary.** Carry forward the existing owner-created master proof. Extend reuse only where ownership, exact teardown, and reconnect are proven. Windows credential and connection behavior needs separate native validation.

OpenSSH remains the transport. The owner resolves supported settings before launch, constructs the private transport configuration, and enforces explicit trust and Disconnect. Ambient masters, unchecked config evaluation, and arbitrary SSH helpers are outside this design. Acceptance and release gates are tracked in the [SSH ownership plan](/Users/youpele/DevWorld/bigbud/docs/plans/2026-11-22-rust-ssh-ownership-plan.md).
