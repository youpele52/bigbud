## 2. Goal and definition of done

### Agreed outcome

Add **Muse Code**, Meta's coding-agent harness, as a first-class bigbud provider. This is not a standalone Meta inference client, a model alias for OpenCode, a browser scraper, or a Meta AI consumer-chat integration.

User decisions, explicitly confirmed during research:

1. Integrate **Muse Code provider**, rather than Muse models through another harness or a direct Meta API provider.
2. Reuse **Muse Code browser sign-in**. Do not request or copy credentials into bigbud.
3. Ship **local-workspace functionality first**: chat/coding, native tool activity, approvals, cancellation, and restart recovery. Remote workspaces, advanced Muse workflows, and background learning are deferred.
4. **Fail closed** on unproven or unavailable access-mode mappings. Never weaken permissions silently or automatically pass `--yolo`.
5. Research and save a plan only. No implementation, dependency installation, test execution, commit or push was authorized or performed by this planner.

### Acceptance criteria

- **AC1 — Setup:** An explicit opt-in Muse Code settings card discovers a user-installed, qualified `muse` binary, reports its version/auth state, and links to official setup. Disabled or missing installations never delay other providers. Existing native browser login works; an API-key override is not silently used instead.
- **AC2 — Selection:** Users choose a real catalog model and supported reasoning effort. Stale/missing models, unknown effort metadata and an empty catalog are truthful states, not fabricated ready models. Existing thread selections are preserved.
- **AC3 — Interactive work:** Two successive turns and two concurrent local threads preserve their own native session/model identities, stream text and tool activity correctly, and produce exactly one truthful canonical terminal outcome per turn. Stop also settles an accepted queued submission: authoritative reclaim yields interrupted; failed launch yields failed even without a start event. Neither path hangs, cancels another turn, nor automatically resubmits input, including after restart.
- **AC4 — Safety:** At least one useful coding access mode is demonstrated equivalent to its bigbud promise. Unsupported modes are disabled with reasons and rejected server-side before tool execution. Approvals, staged commands, questions, cancellation and workspace trust retain native enforcement; no approval is upgraded to a persistent grant.
- **AC5 — Continuity:** Restart resumes only the exact owned native session. Missing/invalid cursors, a foreign writer lease, transport loss, truncated history, and an uncertain send never create a replacement session or execute a fresh-ID duplicate prompt automatically.
- **AC6 — bigbud integration:** Canonical thread tools work through bigbud's existing authenticated MCP bridge, including after resume. Local project/worktree identity, thread deletion fencing and canonical event ownership remain intact.
- **AC7 — Honest limitations:** Remote targets, unverified attachment delivery, plan mode, rewind/fork, steering, advanced workflow controls and unattended workloads are not advertised as supported. Unsupported submissions fail before side effects.
- **AC8 — Regression and delivery:** Existing providers and historical state remain compatible; targeted tests and required repository checks pass. Live qualification records the exact CLI/SDK, operating system, runtime, auth lane and safety configuration for every release target enabled.

Full implementation is **not ready to proceed past Phase 0** until the blocking evidence gates below are closed. A mocked adapter alone does not satisfy AC4 or AC5.

## 3. Background and evidence

### What “Meta Muse” currently means

As researched on **2026-10-13**, Meta's official developer site offers the Muse model family, Meta Model API and Muse Code. Its overview documents `https://api.meta.ai/v1`, OpenAI/Anthropic-compatible inference surfaces, tool calling, streaming and Muse Spark model IDs including `muse-spark-1.3`. Those facts establish an available inference API, not an agent runtime inside bigbud. Muse Code owns the filesystem/shell/tool loop the user requested. [S1–S3]

### Verified published capabilities, not live-tested claims

- Official Muse Code overview links `@muse-code/sdk` and `muse schema`. The official SDK site currently redirects to the **1.4** documentation. npm registry metadata returned **`@muse-code/sdk` 1.4.7**, Node `>=20`, MIT, no runtime dependencies, repository `meta-models/muse-code-sdk`. Returned metadata was JSON, fetched read-only with curl; no package was installed. [S3, S6, S17]
- The 1.4 documentation landing page identifies source commit `d8c53d25bd30cda15ab32b18b9bb9961df9c4be0` and fingerprint `sha256:0d803007acbd02ad07a6cec4d5a63b834f4db743886bbaf865b8738116dc212f`. **This is documentation provenance, not proof that npm 1.4.7 and an installed CLI share that fingerprint.** Record actual handshake evidence in Phase 0. [S6]
- `spawnMspConnection` owns a `muse serve` child. Initialize before traffic, then install notification and server-request handlers before session creation/resume. The connection has one notification handler; replacing it drops the previous handler. Acknowledgements mean admission, not completion. [S7]
- `model/list` works without creating a session. Rows carry native provider/model identities, defaults, optional limits/costs and effort metadata; catalog presence does not prove billing entitlement. `session/setModel` is confirmed by native state/event, not the ack. [S10]
- `session/start`, `session/resume`, `turn/start`, exact-ID `turn/cancel`, `session/read`, `view/page`, `approval/decide` and `userInput/*` are published methods. `account/read`, account login methods and `permissionProfile/list`/selection have experimental surfaces. Negotiate deliberately; do not treat all installed builds as equivalent. [S8, S14]
- **SDK facade limitation:** `StartSessionOptions` explicitly excludes `config` pending facade MCP grant support. The wire `session/start` and `session/resume` do admit `config.mcpServers`; `sessionMcp` is a negotiated capability. Therefore use the official **low-level connection plus SDK fold**, not a cast around `MuseClient.startSession`, if supplying bigbud MCP. [S13]
- MSP command IDs are UUIDv7, with durable deduplication for session/turn admissions. A reused ID with changed payload is a conflict. Turn start IDs derive from command IDs. Cancel/interrupt dedupe is host-lifetime-only: always name the exact turn to avoid affecting new work after restart. [S9]
- Queued submissions already have a turn ID. Exact-ID `turn/unqueue` reclaims queued input; authoritative `turn/unqueued` carries the original submission's command ID, not the unqueue command ID. Reclaim emits neither `turn/started` nor `turn/completed`; launch failure can emit failed `turn/completed` without `turn/started`. These no-run exits must settle independently of running-turn lifecycle. Queued state is durable and appears in `queuedTurns`; absence from that list alone is not reclaim evidence. [S9, S20]
- Full items replace older revisions; deltas append transiently and are not replayed by paging. Completed items are authoritative. Recovery handles inline/snapshot/suffix/none history explicitly; unknown modes are not empty history. Opaque cursors must not be parsed. [S11–S12]
- Permission profiles and approval modes are separate from sandboxing. CLI `untrusted` still allows in-workspace file writes; it is **not** proof of bigbud's “approve all file changes” mode. Auto-review may involve a native reviewer. Staged approvals have requirement identities and server-issued choices/scopes. [S5, S15]
- Native browser login is stored by Muse. `META_API_KEY`, then a stored API key, override browser login. Meta Managed Accounts cannot use browser sign-in. Subscription credentials are Muse-Code-only; additional API keys are pay-as-you-go. **Subscriptions default to Contributor mode**, under which content can train future Meta models. Preserve native settings but disclose this before sending project content; do not imply login means non-training mode or free/unlimited inference. [S4, S18]
- Meta documents macOS, Linux and Windows CLI support. Linux sandbox helper availability and Windows first-use UAC differ. Published platform support is not bigbud packaged-runtime validation. [S3, S5]
- Documentation has a caveat: the concepts guide calls the protocol pre-1.0 and says no changelog, while the compatibility page now links a generated changelog and describes additive evolution with pre-1.0 exceptions. Prefer the specific current compatibility guidance: unknown fingerprint alone warns, unknown fields are tolerated, required missing/incompatible methods fail clearly. Do not promise unconditional backward compatibility. [S8, S16]

### What was not verified

`command -v muse` returned no executable in this environment. No CLI was installed or launched, no native profile inspected, no browser/account login attempted, no model request billed, and no native schema or transcript captured. Actual browser-login entitlement through `muse serve`, Bun/packaged-host behavior, supported permission profiles, profile enforcement across native/MCP/delegated tools, and MCP compatibility remain **unverified**. These are qualification gates, not evidence that the API does not exist.

## 5. Scope

### In scope

- Internal provider key **`muse`**, display name **Muse Code**, optional composition, default disabled.
- User-installed CLI, existing native home/account, explicit enable and install/login guidance; background detection never signs in.
- Local repository/worktree sessions, authoritative native model/effort selection, streamed text/reasoning/tool items, staged approval and question handling, exact-turn cancellation, durable exact-session recovery.
- Existing canonical thread-tool MCP bridge with per-session configuration and ownership/token cleanup; ordinary native coding tools remain Muse-owned.
- Additive settings/contracts, canonical event mapping, persistent identity/admission records, desktop/web UI and mobile selection compatibility, tests and redacted qualification report.

### Explicitly out of scope

- Remote provider execution or local runtime against a remote workspace, a new Rust transport, a separate inference/agent loop, importing arbitrary native sessions or attaching to the user's running TUI session.
- Programmatic sign-in/logout/payment/subscription management; reading native credential files; rewriting native global permissions, workspace trust, Contributor mode, plugins or model defaults.
- First-release fork, rewind, native steering, autonomous goals/workflow control, subagent-control UI, native computer use, voice/video/image-generation support, learning jobs and unattended git-text generation.
- Attachment upload/delivery for the initial milestone. Explicitly reject attachments rather than pretending Meta model multimodality proves harness delivery. Adding text/image delivery requires a follow-up qualification/plan update.
- Native session-file deletion. bigbud thread deletion removes its own resources and fences activity, but retains native history; disclose this retention boundary.
- Separate unsend/queue-management UI or automatic composer restoration. The existing Stop gesture must safely handle the adapter's accepted queued submission; it does not add native steering or another submission flow.

### Unchanged behavior

Do not change global default provider/model/access settings, existing provider ordering rules, canonical thread/turn identities, WebSocket transport, other providers' auth/capabilities, historical OpenCode read-only behavior, or unrelated worktree edits. No blanket provider refactor, new validation framework, or package-manager change.

## 7. Ordered implementation steps

### Phase 0 — Qualify the native contract before product implementation

**Dependencies:** user-installed CLI and authorized account; disposable workspace/profile for experiments. Do not install or log in as an incidental background probe. This phase is future implementation work, not work performed by this planner.

1. Recheck Git/instructions and reconcile concurrent provider work. Create a dated qualification record under `docs/validation/` during implementation with CLI version/platform, exact SDK version, Bun/Node versions, handshake capabilities/durability/schema, documented SDK provenance and redacted scenarios. Start with SDK 1.4.7; use its bundled/generated types and matching published release documentation.
2. Exercise `muse --version`, `muse schema`, then the official low-level SDK with `muse serve`. Verify supported spawn/shutdown, frame limits, handler registration, account-read/profile experimental negotiation, `sessionMcp` grant, durable rather than ephemeral storage, catalog discovery without session creation, and two parallel owned children. A fingerprint mismatch alone is a warning; missing required behavior blocks readiness. Do not override an operator's SDK off-switch.
3. Use existing native browser login for a real model turn. Confirm `accountLogin`, actual plan/model entitlement and post-login recovery. Test logged-out, expired/revoked auth, wrong-account/key precedence, quota exhaustion and offline cases. Never export a subscription token into an inference client. Show Contributor-mode guidance and retain native privacy settings; do not silently choose a training-enabled variant as a cheaper fallback.
4. Build an explicit **access-mode qualification matrix**: bigbud mode; native profile ID; native approval mode; reviewer authority/attachment; sandbox/network policy; file/command/MCP/delegated-action outcomes. Test denied file writes, out-of-root writes, shell execution, staged compound commands, network requests, project hooks/trust and resumed sessions. `promptUnmatched` or CLI `untrusted` alone is not equivalence evidence. If “approval-required” cannot enforce all required changes, it is unsupported; if full-access requires native unrestricted trust, require the same explicit user choice and warning as that privilege, never derive it solely from bigbud's default full-access. Plan mode is unsupported initially, not prompt-only read-only enforcement.
5. Test per-session required stdio MCP with the actual bigbud bridge framing/configuration, current process executable resolution and native policy. Reattach fresh bridge configuration on exact-ID resume without writing the user's `.muse` settings. Test grant refusal and MCP launch failure before any prompt is sent.
6. Capture redacted deterministic transcripts for send ack-loss, duplicate command replay, host death, exact-ID resume, writer-lease conflict, approval reissue, user-input timeout, paged/snapshot history, active-turn inspection and final item replacement. Qualify Stop while queued: establish whether exact-ID cancel settles queued work on this CLI; use exact-ID `turn/unqueue` where required (the documented queued path), confirm `turn/unqueued` identity/durable settlement, and exercise reclaim versus launch races and failed completion without start. Record how replay/resume proves each no-run outcome; missing proof leaves recovery blocked, never inferred from queue disappearance. Prove a real follow-up uses prior context after restart. If critical guarantees fail, stop and revise this plan rather than substitute another harness.

**Exit:** tested CLI/SDK pair; at least one safe usable mode and explicit unsupported-mode reasons; login and MCP qualification; native event/identity/error fixture set. Update the remaining gates before calling later phases implementation-ready. Live failures do not authorize changes to settled scope.

## 9. Risks and rollout

- **Critical safety equivalence:** profile names and mode strings are not permission proofs. Qualification and fail-closed mode metadata are release blockers. Project trust may load hooks and skills; never auto-trust workspaces or bypass sandbox failure to make a test pass.
- **Billing/privacy:** native browser auth may have plan/region restrictions; key precedence changes billing; Contributor defaults affect source-code privacy. Native settings remain authoritative; disclose, verify auth lane, never extract tokens or silently fall back to inference/API keys.
- **Pre-1.0/experimental drift:** pin SDK, document CLI range and handshake/capability evidence; warn on fingerprints but block required incompatibilities. Account/profile experimental APIs must not silently disappear behind an apparently ready snapshot.
- **Durability gaps:** existing runtime cursor updates happen around start/send and do not make every streamed cursor a durable checkpoint. Start with authoritative snapshot reconstruction and stable publication identities, not cursor-only resume. Runtime-directory rollback must not erase native session-creation ownership; use the separate binding table. Native refusals require proven failed settlement, not false accepted states.
- **Resource pressure:** per-thread processes trade memory for clear ownership. Spawn on use, bound startup/probe concurrency and buffers, release idle/closed children only when no pending work, and test multiple threads. Never pool hosts across safety/workspace boundaries merely to reduce memory.
- **MCP and trust:** session-local config is a supported wire surface but not yet in the SDK facade. Request the actual capability, require startup success, use existing per-thread authentication and deny cross-thread actions. Never serialize bridge secrets into resume cursors or browser data.
