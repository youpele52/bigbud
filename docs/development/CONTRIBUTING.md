# Contributing

**bigbud is not accepting external code contributions at the moment.** Please don't open PRs that implement a feature, fix, or refactor, even if the change is small. If we decide to move forward with a proposal, the maintainer will implement it.

Bug reports and feature requests are still welcome as [issues](https://github.com/youpele52/bigbud/issues). If you know what should change but don't have a detailed implementation plan, an issue is the right place to start.

## Pull requests are for plans only

If you've worked out how a change should be implemented, open a **plan-only PR**. Add a Markdown file to the [plans directory](https://github.com/youpele52/bigbud/tree/main/docs/plans), and read a few existing plans there first to see how they're structured. Keep the PR limited to the plan; don't include implementation code.

Write the plan so the maintainer can pick it up and implement it without having to fill in the gaps. Include:

- **Problem and goal:** What happens today, who it affects, and what should happen instead.
- **Scope:** What's in and out of scope, and which parts of the app would change.
- **Implementation steps:** What to change and in what order, including dependencies, trade-offs, and edge cases that matter.
- **Verification:** How to tell the change works and what regressions to check for.

Link the related issue if there is one. A plan PR is a proposal, not a commitment to implement it.
